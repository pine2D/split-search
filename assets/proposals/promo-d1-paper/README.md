# 宣传图方向 d1-paper：纸白 · 精排

一句话：暖白纸底、近黑字、一抹松针绿；页头一栏左对齐，真实截图占画面主体，标注只用 1px 细线和一行小字。

模板在 `assets/templates-d1-paper/`，渲染命令（在仓库根目录运行）：

```bash
node scripts/store/render-assets.mjs --templates assets/templates-d1-paper --out assets/proposals/promo-d1-paper
```

强调色全套只有三种用法：

1. `#507665` 的 1px 线框或箭头（截图上的标注框、拖拽路径、两块截图之间和原理图栏间的箭头）；
2. `#3E5D50` 的文字（截图上方的“① 输入 / ② 回车后”、原理图编号、`_ss` 参数，`_ss` 底下另有 12% 的浅绿底）；
3. 实心 `#507665` 色块，只用在小宣传图左格和顶部宣传图左栏（字反白）。

截图外框：1px `rgba(29,35,32,.13)` 描边，加一层 `0 4px 12px rgba(29,35,32,.06)` 的淡投影，全套一致。没有渐变、发光和紫色、橙色；图标右格的暖雾灰 `#8C8881` 只出现在图标里。

## 字体与字号

只用一个字族：Sarasa UI SC（更纱黑体 UI，拉丁部分是 Inter，中文部分是思源黑体），代码用 Sarasa Fixed SC。本机字体来自 `/mnt/c/Windows/Fonts`，没有从网络加载。

字体栈只写 `"Sarasa UI SC", sans-serif`，不再列 Noto 等后备字体：本机没有 Noto Sans CJK SC，换字体会改变字宽和折行，所以不让它悄悄退回。每个模板都加载 `fonts.js`，它在截图前（`window.beforeCapture`）比较字宽，确认 Sarasa UI SC 和 Sarasa Fixed SC 都在；缺任何一个，这张图就报“缺少字体”渲染失败，`render-assets.mjs` 以非零码退出。换机器渲染前先装更纱黑体，用 `fc-match "Sarasa UI SC"` 确认。

## 版式

- 截图 1：整窗，左右各裁掉 8px 窗口边，缩放 0.497，分屏中缝落在画布中线 640。
- 截图 2、3：同一套版式。左 432 宽是操作的那一刻（地址栏下拉 / 拖拽中），右 704 宽是结果分屏（DuckDuckGo 整个窗格加百度的 logo 和搜索框），两块缩放相同（0.435），中间 48 的间距里一条 1px 箭头。截图上方的边距里用 13px 松针绿字写“① 输入 / ② 回车后”“① 拖到标签栏 / ② 松手后”，左缘对齐各自的截图，不压在截图上。截图 3 左块里另有 1px 细框（选中的文字、标签栏上的拖拽影像）和一条细拖拽路径。
- 截图 4：只放设置页“搜索引擎”一张卡片，缩放 0.819，五个预置引擎都能读清；去掉了原来压在上面的“添加到 Chrome”卡片（一张图只讲一件事，触发网址留给截图 5 和原理图）。
- 截图 5：顶部一条“同一个触发网址”，下面上下两行对照，左栏 48–280 写说明，截图从 312 起。两张截图缩放相同（0.39）：上面是分屏两个窗格的上部，下面是普通 DuckDuckGo 结果页、向下出血；下图只有上图一半宽，正好是“一个引擎”和“两个引擎”的差别。

## 待定

- CWS 对截图的建议是“直角、无留白（满版）”。这套方向是纸底留边的排法，截图本身没有满版；如果要严格照建议，需要另做一版让真实截图铺满 1280×800。
- 截图 2、3 的结果分屏只显示到百度窗格的 logo 和搜索框，百度一侧的正文被块的右缘截掉；要两侧都完整，就得把整窗缩到约 0.29，字会读不清。
- `assets/raw/` 里地址栏和拖拽两组截图的右侧是自定义引擎“百度”（这台机器上 Bing 对中文查询会弹人机验证）。要换成预置引擎，需要重拍。
- 截图里设置页标签仍是 Chrome 生成的灰底“S”图标（`assets/raw/` 拍摄时还没有正式图标），上架前要重拍，见 `docs/store/assets-spec.md` 第 1 节。
