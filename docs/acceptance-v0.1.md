# Split Search v0.1 验收清单

扩展 ID 应为 `alngkkgnobglnfbhcplhpaflcgfiajnj`。默认组合为 **Google ｜ Bing**。

验收只跑 WSL 里的端到端验收（第 1 节）。**Windows 冒烟 v0.1 不做**：2026-10-24 用户决定跳过；第 2 节保留作以后的参考。

## 1. 引导式端到端验收（WSL）

运行 `npm run e2e`。脚本会打开一个独立的 Xephyr 窗口（标题“e2e 测试显示 :N”），测试浏览器全程在这个窗口里。它的鼠标和键盘与你的桌面分开：**你只在向导提示需要你操作时，才到这个窗口里操作，其余时间照常用电脑**，只是别把光标停在这个窗口上。装了 xdotool 等工具时（见下文“真实输入”），拖拽、地址栏、右键这些操作由脚本在窗口里用真实鼠标键盘自动完成。2026-10-24 起整次运行除了偶尔重新登录 Kagi 都不需要你：B14 深色模式（CDP 模拟深色并比对样式表里的颜色）、B4 横幅授权、T8 全部子项（无痕用 CDP 的无痕上下文，停用/启用扩展和“有权访问的网站”检查经 chrome://extensions 详情页）、T9、T12 编辑 Kagi 条目与地址栏输入，都由脚本自动完成并判定。B4、T8 撤销后重新申请的网站之前授权过，Chrome 直接批准，不弹授权框。首次运行仍会引导你安装扩展、授权（这一次要点授权框）、登录 Kagi。

- 显示方式：`--display xephyr`（引导式的默认）开上面说的可见窗口；`--display xvfb` 用不可见的显示（`--auto-only` 的默认；xvfb 只适合 `--auto-only`，引导式运行用 xvfb 时需要你操作的步骤做不了）；`--display host` 是原来的做法，浏览器直接开在你的桌面上，保留作对照。Xephyr 或 Xvfb 没装、起不来时自动退回 host，不算失败，原因打印在终端、写进报告头。报告头的“显示”一行写明本次用的是哪种。退回 host 时，真实输入步骤按下面 host 的光标要求做。
- 测试浏览器是 WSL 里的 Google Chrome 155（带界面），使用独立的测试配置 `~/.cache/split-search-e2e/profile`，不登录 Chrome 账号、不开同步，不碰日常配置。
- 浏览器里会固定打开“Split Search 验收向导”页（`http://127.0.0.1:8765/guide`），它也在 Xephyr 窗口里。如果 WSL 的 localhost 转发可用，你也可以在自己的浏览器里打开这个网址只看进度；复制网址仍然要用 Xephyr 窗口里的向导页。照着向导页的说明操作即可：
  - **auto**：脚本自己做、自己判；
  - **xauto**（真实输入）：脚本用 xdotool 发真实的鼠标键盘事件（拖文字到标签栏、右键、在新开窗口的地址栏输入），再自己判定。这些事件只发给测试浏览器所在的显示：
    - Xephyr / Xvfb（默认）：脚本自己把窗口里的指针移到位，你可以照常用电脑，**只是别把光标停在 Xephyr 窗口上**。光标在窗口上移动时，真实移动会被转发进去，手势会中止重来，向导页会提示“指针被用户光标带走（请把光标移出测试窗口 Xephyr）”。Xvfb 不可见，什么都不用管。
    - host（`--display host` 或退回时）：**把鼠标光标停在测试浏览器窗口里，然后把手从鼠标/触摸板上拿开**：WSLg 下手只要碰到鼠标，X 指针就会被拉回真实光标位置，手势会中止重来（向导页会提示“指针被拉回真实光标位置”）。光标不在测试窗口上时向导页提示“光标不在测试窗口上”，最多等 30 秒，等不到这一步记“跳过”。
  - **assist**：你按说明操作（首次安装扩展、登录 Kagi，以及没有真实输入或自动版本做不了时的回退），脚本检测到预期的状态就判通过；做不了点“跳过”，没反应可以点“重试”；
  - **judge**：只能人眼判断的，你点“通过 / 不通过 / 跳过”。现在只出现在回退路径里（T6-NTP、T12 没有真实输入时；T8(a)(d) 自动版本做不了时）。
  - assist 和 judge 都在 Xephyr 窗口里做。**Windows 剪贴板和 Xephyr 不通**：要复制网址（触发网址、`&_ss=kagi,bing` 等）时，点窗口内向导页的“复制”按钮，再在窗口里粘贴，不要从 Windows 那边复制进去。
- 真实输入的前提：`xdotool`、`import`（ImageMagick）、`xdpyinfo`、`xwininfo` 可执行（`xprop` 可选），X 服务器带 XTEST 扩展，浏览器带界面（Xephyr、Xvfb 下总是带界面）。嵌套显示另需 `Xephyr`（`sudo apt install xserver-xephyr`）或 `Xvfb`。不满足、或传了 `--no-xinput` 时，这些步骤自动换成人工协助版本（你自己拖拽、在地址栏输入、右键，并按提示在 `chrome://settings/searchEngines` 添加 `gb` 等网站搜索），不算失败。
- 真实输入步骤用的网站搜索是脚本自动添加的 `sse2e` 专用条目（只指向模拟引擎；T14 用 `sse2e-<引擎 id>` 指向各预置引擎），结束时（含 Ctrl+C 中断）自动删除并恢复原来的默认搜索引擎，不需要你动手。有这类步骤时，测试窗口固定为 1600×1000。
- 第一次运行时的一次性准备由向导带着做：在 `chrome://extensions` 打开开发者模式并用“加载未打包的扩展程序”加载仓库的 `src/`（同时验证 B1）；点一次授权框（模拟引擎 + 五个预置引擎的网站）；需要 Kagi 的步骤前在 kagi.com 登录。之后都保存在测试配置里。
- Google 偶尔会弹人机验证页（`google.com/sorry`），向导会提示你完成验证后继续。
- 人工协助路径里添加的网站搜索（`gb`/`bg`/`dg`/`px`/`kg`），以及 T12 给 Kagi 条目追加的 `_ss`，只存在于隔离的测试配置里，不用恢复，下次运行会复用。默认搜索引擎：脚本改过默认时（真实输入步骤的 `sse2e` 条目、T12 把 Kagi 条目设为默认），收尾恢复为运行前的默认；人工协助路径里你自己设的默认保留。只有 T8(d) 在人工回退路径里改过扩展详情页的“有权访问的网站”时，收尾才提示改回“在特定网站上”。
- 回退：没有真实输入（`--no-xinput` 或工具不全）时，T1–T6-NTP、T11、T12、T14 换回人工协助/判断版本；自动步骤遇到测试设施问题（扩展详情页打不开或结构变了、建不了无痕上下文、找不到 Chrome 自动发现的 Kagi 条目）时，引导式运行改由你按向导操作，`--auto-only` 记“跳过”并写明原因。
- 报告写到 `.e2e/report-<时间>.md` / `.json`；网址里的 token、session、sid、auth、key、code 以及 `*_token`、session_id 等参数值会被替换成 `***`。中途中断或出错时，若有需要改回的设置（目前只有 T8(d) 的“有权访问的网站”），也会打印在终端并写进报告备注。
- 结果有四种：通过、失败、跳过、**预期降级**。预期降级只用于 T14：某引擎作左侧时，触发前就检测到它的 Service Worker、没分屏、左侧停在该引擎上并带着这次的查询词，并且没有扩展接管过这次触发的迹象（跳转链里没有带这次查询词的 go.html、没有新增扩展控制台错误、没有孤立的 Google 右侧标签）——这是 G5 的已知行为，单独计数、不算失败、不影响退出码，报告据此建议给该引擎设“仅建议作右侧”。没检测到 SW 却没分屏仍算失败。多子项步骤里跳过或预期降级的子项，在步骤整体通过或预期降级时写在汇总说明的第一行；无论步骤结果如何，都会列进报告的“未覆盖”小节。
- 日常回归用 `npm run e2e -- --auto-only`，前提是已完成过一次完整的引导式运行。它默认在不可见的 Xvfb 里跑，完全无人值守，xauto 步骤也照跑，不影响你用电脑。它不等 Kagi 登录：T9、T12 先探测一次，没登录就记“跳过”（原因写进报告），这时跑一次引导式运行登录 Kagi 即可。想看着它跑，加 `--headed` 改用 Xephyr 窗口。退回 host 时（Xvfb 不可用），`--auto-only` 是无头的，没有真实输入，xauto 步骤不执行；这时要连同 xauto 一起回归，得加 `--headed`，并按上面 host 的要求把光标停在测试窗口里、手离开鼠标。
- 运行结束（含 Ctrl+C 中断、出错）后，脚本会停掉自己起的 Xephyr/Xvfb。万一残留，下次启动时按 `.e2e/display.pid` 清理，只清理它自己起的，不碰你的桌面或别的显示。

## 2. Windows Chrome 冒烟（v0.1 不做）

2026-10-24 用户决定 v0.1 跳过这一节，T3(b)（从外部 Windows 应用拖入）和 Windows 环境本身的问题因此在 v0.1 未覆盖。以下保留作以后的参考。

WSL 覆盖不到 Windows 环境本身，以及从 Windows 应用拖入。在 Windows Chrome 155+ 里做这 6 项：

1. 在 WSL 运行 `bash scripts/sync-to-windows.sh`；`chrome://extensions` 里“加载未打包的扩展程序”选 `D:\APP\Chrome-Extensions\split-search`（已加载过就点“重新加载”，不要移除重装），核对扩展 ID 为 `alngkkgnobglnfbhcplhpaflcgfiajnj`，并在设置页横幅里授权 Google 和 Bing。
2. 在 `chrome://settings/searchEngines` 添加网站搜索 `gb`（网址 `https://www.google.com/search?q=%s&_ss=google,bing`）并设为默认，然后从记事本拖一段文字到标签栏（T3b）：出现 Google ｜ Bing 分屏。
3. 在普通网页上选中一段文字，拖到标签栏两个标签之间：出现 Google ｜ Bing 分屏。
4. 在地址栏直接输入关键词回车（用默认引擎 `gb`）：出现 Google ｜ Bing 分屏。

5. Chrome 切到英文界面后，设置页（语言保持“跟随浏览器”）、go.html、工具栏按钮标题都是英文（i18n 方案 9.4）。
6. Chrome 保持中文、设置页语言选西班牙语：设置页和 go.html 出错页变成西班牙语，工具栏按钮标题仍是中文（符合 i18n 方案 5.1 的限制）。

结束后把默认搜索引擎改回原来的，删掉 `gb`。

## 3. 原 B/T 表（参考，注明覆盖方式）

“覆盖”一列（2026-10-24 更新）：**e2e auto** = 脚本全自动（`--auto-only` 也跑）；**e2e 自动（真实输入）** = xauto 步骤，脚本用真实鼠标键盘操作并判定（前提见第 1 节，不满足时用后面写的回退方式；除 T14 外都用模拟引擎 A ｜ B 代替 Google ｜ Bing，链路相同）；**e2e assist** = 向导指导你操作、脚本判定；**e2e judge** = 向导里由你判断；**Windows 冒烟** = 第 2 节（v0.1 不做，等同未覆盖）；**未覆盖** = v0.1 不测或需要时手测。e2e 里的“核心链路”（CORE-NEW、CORE-EXISTING：用模拟引擎触发，相当于拖到两个标签之间、拖到已有标签上）单独列在报告里，不算作 T3/T4 通过。e2e 运行时调试会话一直连着扩展的 Service Worker，SW 不会被空闲回收，所以测不到“SW 回收后冷启动”的问题（例如依赖 `storage.session` 的“本扩展分屏”判定）；这类问题靠手测（第 2 节的 Windows 冒烟 v0.1 不做）。

## 4. 反馈方式

把整份 e2e 报告（`.e2e/report-*.md`，同名 `.json` 内容相同）贴回给 Claude（v0.1 不做 Windows 冒烟）。汇总表每步只显示说明的第一行；多子项步骤的计数与各子项（T2、T5、T6、T7、T8、T10、T12、T13、T14）、T12 的联想截图路径、T8(d) 是否“不适用”、T14 每个引擎的现象，都完整写在报告的“失败详情”或“详细说明”小节里，“未覆盖”小节列出 e2e 不测的项目，以及本次运行里跳过或预期降级的子项。全部通过后，Claude 再打 `v0.1.0` 标签。
