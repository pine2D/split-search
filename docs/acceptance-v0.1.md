# Split Search v0.1 验收清单

扩展 ID 应为 `alngkkgnobglnfbhcplhpaflcgfiajnj`。默认组合为 **Google ｜ Bing**。

验收分两段：先在 WSL 里跑引导式端到端验收（覆盖绝大多数项目），再在 Windows Chrome 里做 4 项冒烟。

## 1. 引导式端到端验收（WSL）

运行 `npm run e2e`。装了 xdotool 等工具时（见下文“真实输入”），拖拽、地址栏、右键这些操作由脚本用真实鼠标键盘自动完成，整次运行基本无人值守：你只需回答判断题（B14 深色模式、T8(a) 无痕窗口、T8(d) 站点访问、T12 的联想），点必要的授权弹窗（B4、T8(c)(e) 恢复授权），以及做 T8(b) 停用/启用扩展、T12 编辑 Kagi 条目这几处操作。首次运行还会引导你安装扩展、授权、登录 Kagi。

- 测试浏览器是 WSL 里的 Google Chrome 155（带界面），使用独立的测试配置 `~/.cache/split-search-e2e/profile`，不登录 Chrome 账号、不开同步，不碰日常配置。
- 浏览器里会固定打开“Split Search 验收向导”页（`http://127.0.0.1:8765/guide`）。照着向导页的说明操作即可：
  - **auto**：脚本自己做、自己判；
  - **xauto**（真实输入）：脚本用 xdotool 发真实的鼠标键盘事件（拖文字到标签栏、右键、在新开窗口的地址栏输入），再自己判定。这类步骤进行时，**把鼠标光标停在测试浏览器窗口里，然后把手从鼠标/触摸板上拿开**：WSLg 下手只要碰到鼠标，X 指针就会被拉回真实光标位置，手势会中止重来（向导页会提示“指针被拉回真实光标位置”）。光标不在测试窗口上时向导页提示“光标不在测试窗口上”，最多等 30 秒，等不到这一步记“跳过”。
  - **assist**：你按说明操作（点授权框、停用扩展等），脚本检测到预期的状态就判通过；做不了点“跳过”，没反应可以点“重试”；
  - **judge**：只能人眼判断的，你点“通过 / 不通过 / 跳过”。
- 真实输入的前提：`xdotool`、`import`（ImageMagick）、`xdpyinfo`、`xwininfo` 可执行（`xprop` 可选），X 服务器带 XTEST 扩展，浏览器带界面。不满足、或传了 `--no-xinput` 时，这些步骤自动换成人工协助版本（你自己拖拽、在地址栏输入、右键，并按提示在 `chrome://settings/searchEngines` 添加 `gb` 等网站搜索），不算失败。
- 真实输入步骤用的网站搜索是脚本自动添加的 `sse2e` 专用条目（只指向模拟引擎；T14 用 `sse2e-<引擎 id>` 指向各预置引擎），结束时（含 Ctrl+C 中断）自动删除并恢复原来的默认搜索引擎，不需要你动手。有这类步骤时，测试窗口固定为 1600×1000。
- 第一次运行时的一次性准备由向导带着做：在 `chrome://extensions` 打开开发者模式并“加载已解压”仓库的 `src/`（同时验证 B1）；点一次授权框（模拟引擎 + 五个预置引擎的网站）；需要 Kagi 的步骤前在 kagi.com 登录。之后都保存在测试配置里。
- Google 偶尔会弹人机验证页（`google.com/sorry`），向导会提示你完成验证后继续。
- 人工协助路径里添加的网站搜索（`gb`/`bg`/`dg`/`px`/`kg`）、默认搜索引擎、Kagi 条目追加的 `_ss` 只存在于隔离的测试配置里，不用恢复，下次运行会复用。只有 T8(d) 改过扩展详情页的“站点访问”（assist 回退路径）时，收尾才提示改回“在特定网站上”。
- 报告写到 `.e2e/report-<时间>.md` / `.json`；网址里的 token、session、sid、auth、key、code 以及 `*_token`、session_id 等参数值会被替换成 `***`。中途中断或出错时，若有需要改回的设置（目前只有 T8(d) 的站点访问），也会打印在终端并写进报告备注。
- 结果有四种：通过、失败、跳过、**预期降级**。预期降级只用于 T14：某引擎作左侧时，触发前就检测到它的 Service Worker、没分屏、左侧停在该引擎上并带着这次的查询词——这是 G5 的已知行为，单独计数、不算失败、不影响退出码，报告据此建议给该引擎设“仅建议作右侧”。没检测到 SW 却没分屏仍算失败。多子项步骤里跳过或预期降级的子项会写在汇总说明的第一行，并列进报告的“未覆盖”小节。
- 日常回归用 `npm run e2e -- --auto-only`（无头、无人值守），前提是已完成过一次完整的引导式运行。无头时没有真实输入，xauto 步骤不执行；要连同 xauto 一起回归，用 `npm run e2e -- --auto-only --headed`，并按上面的要求把光标停在测试窗口里、手离开鼠标。

## 2. Windows Chrome 冒烟

WSL 覆盖不到 Windows 环境本身，以及从 Windows 应用拖入。在 Windows Chrome 155+ 里做这 4 项：

1. 在 WSL 运行 `bash scripts/sync-to-windows.sh`；`chrome://extensions` 里“加载已解压的扩展程序”选 `D:\APP\Chrome-Extensions\split-search`（已加载过就点“重新加载”，不要移除重装），核对扩展 ID 为 `alngkkgnobglnfbhcplhpaflcgfiajnj`，并在设置页横幅里授权 Google 和 Bing。
2. 在 `chrome://settings/searchEngines` 添加网站搜索 `gb`（网址 `https://www.google.com/search?q=%s&_ss=google,bing`）并设为默认，然后从记事本拖一段文字到标签栏（T3b）：出现 Google ｜ Bing 分屏。
3. 在普通网页上选中一段文字，拖到标签栏两个标签之间：出现 Google ｜ Bing 分屏。
4. 在地址栏直接输入关键词回车（用默认引擎 `gb`）：出现 Google ｜ Bing 分屏。

结束后把默认搜索引擎改回原来的，删掉 `gb`。

## 3. 原 B/T 表（参考，注明覆盖方式）

“覆盖”一列：**e2e auto** = 脚本全自动；**e2e 自动（真实输入）** = xauto 步骤，脚本用真实鼠标键盘操作并判定（前提见第 1 节，不满足时用后面写的回退方式；除 T14 外都用模拟引擎 A ｜ B 代替 Google ｜ Bing，链路相同）；**e2e assist** = 向导指导你操作、脚本判定；**e2e judge** = 向导里由你判断；**Windows 冒烟** = 第 2 节；**未覆盖** = v0.1 不测或需要时手测。e2e 里的“核心链路”（CORE-NEW、CORE-EXISTING：用模拟引擎触发，相当于拖到两个标签之间、拖到已有标签上）单独列在报告里，不算作 T3/T4 通过。e2e 运行时调试会话一直连着扩展的 Service Worker，SW 不会被空闲回收，所以测不到“SW 回收后冷启动”的问题（例如依赖 `storage.session` 的“本扩展分屏”判定）；这类问题靠第 2 节的 Windows 冒烟或手测。

## 4. 反馈方式

把整份 e2e 报告（`.e2e/report-*.md`，同名 `.json` 内容相同）贴回给 Claude，再加上 Windows 冒烟里不通过的项。汇总表每步只显示说明的第一行；多子项步骤的计数与各子项（T2、T5、T6、T7、T8、T10、T13、T14）、T12 的联想回答、T8(d) 是否“不适用”、T14 每个引擎的现象，都完整写在报告的“失败详情”或“详细说明”小节里，“未覆盖”小节列出 e2e 不测的项目，以及本次运行里跳过或预期降级的子项。全部通过后，Claude 再打 `v0.1.0` 标签。
