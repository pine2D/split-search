# 多语言（i18n）设计与排期

日期：2026-10-24　作者：pine2D　状态：**草稿，待用户审批**（只写方案，不动代码）
关联：`2026-10-23-split-search-design.md`（主设计）、`docs/store/*`（商店详情、隐私、素材）、`CLAUDE.md`（硬约束与非目标）

## 1. 意图

用户已决定（2026-10-24 对话）：首期支持英文、繁体中文、简体中文，再加上全球使用人数前五以内的其他语言。

扩展上架 Chrome 网上应用店（CWS）以后，面向的不只是简体中文用户。目前设置页、go.html 出错页、manifest 简介和工具栏按钮标题全部写死为简体中文，非中文用户装上以后看不懂设置页，而设置页恰好是本扩展必须走一遍的流程（授权、复制触发网址、添加网站搜索）。本方案把所有界面文案改成走 Chrome 自带的 `chrome.i18n`，在扩展包里放 6 种语言的文案，并给每种语言出一份商店详情。

**本方案要改动项目约定（需用户批准）：**

## 2. 首期语言

### 2.1 使用人数排名（核实结果）

来源：Ethnologue 2026 版《The Ethnologue 200》（https://www.ethnologue.com/insights/ethnologue200/ ），排名口径为母语加第二语言的总人数（L1+L2）。完整表格的数字转引自 Wikipedia “List of languages by total number of speakers” 的 “Ethnologue (2026)” 一节（2026-10-24 查阅）。Ethnologue 按单个语言排名，不算宏语言（“汉语”“阿拉伯语”这类总称不进榜，所以第 2 名是 Mandarin Chinese，第 5 名是 Modern Standard Arabic，即现代标准阿拉伯语）。

| 排名 | 语言 | 总人数（百万） | 首期是否支持 |
|---|---|---|---|
| 1 | 英语 English | 1,493 | 是，`en` |
| 2 | 官话 Mandarin Chinese | 1,183 | 是，`zh_CN` 简体 + `zh_TW` 繁体 |
| 3 | 印地语 Hindi | 611 | 是，`hi` |
| 4 | 西班牙语 Spanish | 561 | 是，`es` |
| 5 | 现代标准阿拉伯语 Modern Standard Arabic | 335 | 是，`ar`（见 2.2） |
| 6 | 法语 French | 334 | 否（见 2.2） |
| 7 | 孟加拉语 Bengali | 274 | 否 |

结论：前五名为英语、官话、印地语、西班牙语、阿拉伯语；扣除已列入的英语和官话（简体、繁体），首期另加印地语、西班牙语、阿拉伯语，共 6 个语言目录。

“及其他全球使用人数前五以内的语言”也可以读成“另加五种”。本方案按“前五名里除中英之外的语言”理解，这是解释而不是原话，已列入第 13 节问题 9 请用户确认。

### 2.2 第 5 名有争议：阿拉伯语还是法语

- Ethnologue 2026 中阿拉伯语 335 百万、法语 334 百万，只差 100 万，远小于这类估算本身的误差。
- 另一个常被引用的来源 CIA World Factbook（2022）把法语和阿拉伯语并列为 3.4%，排序是法语在前。
- 现代标准阿拉伯语没有母语使用者（L1 = 0），人数全部来自第二语言；各地人日常说的是埃及、黎凡特等方言。界面文案用标准阿拉伯语书写是惯例，这一点不影响选择。

**建议：首期选阿拉伯语。** 理由：按最新一版 Ethnologue，它就是第 5 名，用户说的“前五以内”按这个口径落到阿拉伯语上。代价也要写明：阿拉伯语是从右往左书写（RTL），设置页和 go.html 要做镜像布局（第 6 节），还需要母语者审校（第 10 节）。法语是从左往右书写，成本低得多。如果用户想控制成本，可以改成法语，或者阿拉伯语和法语都上（法语的增量工作量很小，见第 12.2 节）。这是第 13 节的问题 2。

### 2.3 扩展包里的语言目录

CWS 支持的语言代码是固定列表（Chrome 文档 `chrome.i18n` 的 Locales 一节）。用了列表以外的代码，Chrome 会直接忽略那个目录。

| 目录 | 覆盖 | 说明 |
|---|---|---|
| `_locales/en` | 所有英语区（`en_US`、`en_GB`、`en_AU` 去掉地区后都落到 `en`） | 也是 `default_locale`，见第 3 节 |
| `_locales/zh_CN` | 简体中文 | 源文案 |
| `_locales/zh_TW` | 繁体中文（台湾） | 香港、澳门见 2.4 |
| `_locales/es` | 所有西班牙语区（`es_419` 去掉地区后落到 `es`） | 用中性的拉美/西班牙通用写法，避免 vosotros |
| `_locales/hi` | 印地语（天城文） | |
| `_locales/ar` | 阿拉伯语 | RTL |

### 2.4 繁体中文：zh_TW 和 zh_HK

- CWS 的语言列表里只有 `zh_CN` 和 `zh_TW`，没有 `zh_HK`，建了 `_locales/zh_HK` 也会被忽略。
- `chrome.i18n` 找文案的顺序是：浏览器界面语言（如 `zh_HK`）→ 去掉地区（`zh`）→ `default_locale`。`zh` 不在支持列表里，不能建。所以只看这条规则的话，香港用户会落到 `default_locale`（英文）。
- 但 Chromium 自己在决定浏览器界面语言时，按 `l10n_util` 的映射会把 `zh-HK`、`zh-MO` 归到 `zh-TW`、`zh-SG` 归到 `zh-CN`。如果这条映射成立，香港用户的 `chrome.i18n.getUILanguage()` 就是 `zh-TW`，会直接用上 `zh_TW` 目录。**这是凭对 Chromium 源码的记忆推断的，没有实测**，排进第 12 节的 spike S1：用 Chrome 155 以 `LANGUAGE=zh_HK` 启动，读 `getUILanguage()`。
- 用词：`zh_TW` 按台湾惯用语写（網址、搜尋引擎、設定）。Chrome 自己的 zh-TW 界面也是这样，香港用户日常看到的 Chrome 就是这套词，所以不另做港式用词。Chrome 界面上的专有名称（“網站搜尋”“設為預設”“分割畫面”之类）一律照抄 Chrome 155 zh-TW 界面的原文，见第 10 节的术语表。

## 3. default_locale：建议 `en`

`default_locale` 只决定两件事：浏览器界面语言不在这 6 种里时显示哪种，以及 CWS 详情的默认语言。它不决定谁是源文案。

**建议 `en`，理由：**
1. 界面是法语、德语、日语、葡萄牙语、俄语、韩语等其他语言的用户，会落到 `default_locale`。对他们来说英文比简体中文好懂得多。
2. CWS 对没有提供本地化详情的地区展示默认语言的详情，英文覆盖面最大。
3. 香港用户如果真的落到默认语言（2.4 的映射不成立时），看到英文也比看到简体好接受。

**代价和处理：**
- 作者的母语是中文，源文案仍然是 `zh_CN`：先写中文、润色定稿，再出英文（第 10 节）。`default_locale` 设成 `en` 不影响这个流程。
- `default_locale` 那份文件必须包含每一个 key（否则 `getMessage` 返回空串）。`test/i18n-catalog.test.js` 要求 6 份文件的 key 集合完全相同，这一条自然满足。
- 现在 CWS 上还没有任何已发布版本，第一次上传时就带 `default_locale`，不存在“改默认语言导致已有详情失效”的问题。

备选是 `zh_CN`：不在这 6 种语言里的用户会看到简体中文，不推荐。

## 4. 文案目录（messages.json）

### 4.1 位置与格式

`src/_locales/<语言>/messages.json`，Chrome 标准格式。每条都写 `description`，给翻译看上下文和长度限制：

```json
{
  "options_pair_title": {
    "message": "默认组合",
    "description": "设置页第一张卡片的标题。默认组合 = 地址栏默认搜索时使用的左右两个引擎。"
  },
  "go_err_unknown_engine": {
    "message": "未知引擎：$ENGINE_ID$",
    "description": "go.html 出错页。触发网址里的 _ss 写了一个不存在的引擎 id。",
    "placeholders": {
      "engine_id": { "content": "$1", "example": "nope" }
    }
  }
}
```

### 4.2 命名

- 只用小写字母、数字、下划线（`chrome.i18n` 的 key 不区分大小写，统一小写可以避免两个 key 实际撞名）。
- 前缀表示出现位置：`ext_`（manifest）、`go_`（go.html）、`options_`（设置页静态结构）、`engine_`（引擎列表与对话框）、`guide_`（触发网址卡片）、`notice_`（右下角提示）、`err_`（`src/lib` 和 `edits.js` 返回的错误码，见 5.3）、`common_`（取消、保存、复制、关闭等通用按钮）。
- 一句完整的话对应一个 key。**不准拼句子**：现在的 `confirmRemoval(e, "隐藏")` 拼出 `隐藏“X”？`、`act(..., \`已隐藏“${e.name}”\`)`、`` `已${verb}“…”` `` 这些写法在别的语言里语序不对，要拆成 `engine_confirm_hide`、`engine_confirm_delete`、`notice_hidden`、`notice_deleted` 等各自完整的句子。

### 4.3 占位符

- 一律用具名占位符（`$ENGINE$`），`content` 写 `$1`…`$9`（Chrome 最多 9 个），`example` 必填。这样翻译可以随意调整语序。
- 引擎名、网址、id、数字上限这些运行时值都走占位符，不写进文案。
- 文案里的字面 `$` 写成 `$$`。
- 引号、冒号、句末标点写在各语言自己的文案里（中文“”和全角冒号，繁体「」，英文 " "，西班牙语 « » 或 " "，阿拉伯语 « »），代码不拼标点。
- 现在 `${dl.name} ｜ ${dr.name}` 用的全角竖线，改成 `guide_pair_label`（`$LEFT$ ｜ $RIGHT$`），英文等语言写 `$LEFT$ | $RIGHT$`。

### 4.4 规模估计

按 2026-10-24 本分支 `src/` 粗数，界面文字约 160 条：`options.html` 约 32、`options.js` 约 27、`engine-list.js` 约 27、`edits.js` 约 16、`go.js` 约 16、`guide.js` 约 13、`ui.js` 约 10、`lib/engines.js` + `lib/trigger.js` 约 13、`go.html` 4、manifest 2。拆掉拼句后会略多，按 170 条估算。`console.error` 里的开发日志（`split-actions.js` 等约 8 条）不算界面文字，不翻译。

## 5. 页面怎么取文案（无构建、无依赖）

保持“无构建工具、无运行时依赖”的约束：不引入 i18next 之类的库，也不做编译期替换，全部在运行时调用 `chrome.i18n.getMessage`。

### 5.1 manifest

```json
"default_locale": "en",
"name": "Split Search",
"description": "__MSG_ext_description__",
"action": { "default_title": "__MSG_ext_action_title__" }
```

`name` 保持字面量 `Split Search`，各语言都不翻译（品牌名，见第 7 节；是否给某些语言加副标题是第 13 节问题 5）。如果要按语言给不同名字，再改成 `__MSG_ext_name__`。

### 5.2 两个新文件

- `src/chrome/i18n.js`（碰 `chrome.i18n`，所以放 `src/chrome/`）：
  - `t(key, ...subs)`：调 `chrome.i18n.getMessage`；返回空串时（key 不存在）记一条 `console.error("[split-search] missing message", key)` 并返回 key 本身，让问题在界面上能被看出来，同时被 e2e 的“无 [split-search] 控制台错误”步骤（B15）抓到。
  - `applyI18n(root = document)`：扫描静态 HTML 里的 `data-i18n="key"`（写 `textContent`）和 `data-i18n-attr="placeholder:key;aria-label:key;title:key"`（写属性）。
  - `setDocumentLocale()`：用 `@@ui_locale`（`zh_TW` → `zh-TW`）设置 `<html lang>`，用 `@@bidi_dir` 设置 `<html dir>`；同时设置 `document.title`。
  - `tNodes(key, nodes)`：处理带内联元素的句子（见 5.4）。
- `src/lib/i18n-format.js`（纯逻辑，不碰 `chrome`，有 node 测试）：把含标记的字符串切成“文字段 / 第 n 个节点”的序列；给占位符值加双向隔离符（见 6.3）。

两个文件都远低于 300 行的单文件上限。`engine-list.js`、`options.js` 现在 180 行左右，把字面量换成 `t("…")` 后行数基本不变。

### 5.3 `src/lib` 和 `edits.js` 返回错误码，不返回句子

`src/lib/` 不能引用 `chrome`，所以拿不到 `getMessage`。现在 `validateTemplate`、`parseTrigger`、`addEngine` 等返回的是中文句子（`{ ok: false, error: "未知引擎：nope" }`）。改成返回错误码和参数，由页面层翻译：

```js
// 改前
return { ok: false, error: `未知引擎：${ids[i]}` };
// 改后
return { ok: false, error: { code: "unknown_engine", args: [ids[i]] } };
// 页面层
showError(t("err_" + parsed.error.code, ...parsed.error.args));
```

`throw new Error(...)` 的地方（`trigger.js` 生成触发网址、`config-store.js` 的“配置过大”）给 Error 加 `code` 属性。`ui.js` 的 `errorText()` 对配额错误同样返回 key。错误码集中导出为一个常量表（如 `ERROR_CODES`），catalog 测试据此检查每个码都有 `err_<code>` 文案。

这样做还有一个好处：单元测试改为断言错误码，不再断言中文句子（第 9 节）。

### 5.4 带内联元素的句子

设置页有几句话中间夹着 `<code>`（`<code>%s</code>`、`<code>gb</code>`、`chrome://settings/searchEngines`）。规则是**永远不用 `innerHTML`**（`ui.js` 现有的约定）。做法：文案里用占位符代表这个元素（`"网址模板中用 $CODE$ 代表关键词。…"`），`tNodes(key, [h("code", null, "%s")])` 先用私有区字符作标记取出文字，再按标记切开、把节点插回去。翻译只需要把 `$CODE$` 放到正确位置。

### 5.5 首屏闪烁

- 设置页 `<body class="loading">` 已经在渲染完成前隐藏内容，`applyI18n()` 放在移除 `loading` 之前执行即可。
- go.html 正常情况下立刻跳走。静态 HTML 里的文字改为空，`go.js` 一开始就 `applyI18n()`，不会先闪中文再变别的语言。

### 5.6 跟随浏览器语言，不做页内切换（建议）

`chrome.i18n` 只认浏览器界面语言，不能在运行时换。要做“设置页里选语言”，就得自己 `fetch(chrome.runtime.getURL("_locales/<l>/messages.json"))`、自己实现占位符替换，再加一个存储项，manifest 的简介和按钮标题仍然只跟浏览器走。建议 v0.2 只跟随浏览器语言，页内切换等有用户反馈再做。这是第 13 节问题 1。

如果实现页内切换，扩展代码里就会出现 `fetch`，和 `docs/store/privacy.md`“代码事实速查”里“没有 `fetch`”的说法冲突。届时要同步把那一行改成“只 `fetch` 扩展包内的文件（`chrome-extension://` 下的 `_locales`），不发任何外部请求”，隐私政策里“不发网络请求”也要相应改为“不向任何外部服务器发请求”。

## 6. 从右往左（阿拉伯语）

### 6.1 方向

`setDocumentLocale()` 用 `@@bidi_dir` 给 `<html>` 设 `dir="rtl"`，浏览器会自动镜像 flex 行、列表缩进、文字对齐。要改的是 CSS 里写死左右的地方。

### 6.2 CSS 改用逻辑属性

按 2026-10-24 本分支逐条核对：

| 文件:行 | 现在 | 改为 |
|---|---|---|
| `options.css:160` | `.steps, .caveats { padding-left: 22px }` | `padding-inline-start` |
| `options.css:170` | `.engine-row.in-pair { box-shadow: inset 3px 0 0 …; padding-left: 12px }` | 改成 `border-inline-start: 3px solid var(--accent)`（inset 阴影没有逻辑写法）+ `padding-inline-start` |
| `options.css:220` | `.notices { right: 16px }` | `inset-inline-end: 16px` |
| `options.css:230,234,235` | `border-left`、`border-left-color` | `border-inline-start`、`border-inline-start-color` |
| `options.css:216` | `.dialog-actions { justify-content: flex-end }` | 不用改，flex 会随方向镜像 |
| `go.html` 内联样式 | `#error { text-align: left }` | `text-align: start` |

`margin: 0 auto`、四边相同的 `padding` 不受影响。以后新写 CSS 一律用逻辑属性，写进 `CLAUDE.md`。

### 6.3 混排

- 网址、网址模板、`chrome://settings/searchEngines`、引擎 id 这些框（`.url-box`、`.mono`、`#dlg-url`、`#dlg-id`）固定 `dir="ltr"`，否则 RTL 下网址里的 `/`、`?`、`%s` 会被重新排列。
- 占位符插入的引擎名、网址在 RTL 句子里两端加 U+2068 / U+2069（FSI / PDI，双向隔离），避免拉丁字母的引擎名把阿拉伯语标点“吸”到错误的一侧。`confirm()` 原生对话框是纯文本，同样适用。统一在 `i18n-format.js` 里做，所有语言都加（对 LTR 语言没有可见影响）。
- ↑ ↓ 排序按钮是上下方向，不需要镜像。

### 6.4 “左侧 / 右侧”的含义要实测（spike S2）

本扩展的核心概念是“左侧引擎”和“右侧引擎”。Chrome 在 RTL 界面下会镜像整个浏览器界面，分屏里排在前面的标签（本扩展的“左侧”）很可能显示在**右边**。如果是这样，阿拉伯语文案不能直译“左/右”，要改成“主/副”或“第一个/第二个”，甚至所有语言都换成不依赖方向的说法。在 Chrome 155 中用 `LANGUAGE=ar` 带界面（Xvfb，显示号 ≥ :140）建一次分屏、截图确认，结论决定 `ar` 的术语。

### 6.5 字体

go.html 写死了 `"Microsoft YaHei UI", "PingFang SC"`（简体字形）。改为按 `:lang()` 选字体：`:lang(zh-TW)` 用 `"Microsoft JhengHei UI", "PingFang TC"`，`:lang(hi)` 用 `"Nirmala UI"`，`:lang(ar)` 用 `"Segoe UI"`。`<html lang>` 设对之后，`system-ui` 也会挑对字形。设置页同理。

## 7. 不翻译的内容

- 产品名 `Split Search`。
- 预置引擎名（Google、Bing、DuckDuckGo、Perplexity、Kagi）和用户自定义的引擎名。
- 网址、网址模板、`%s`、`_ss`、引擎 id、`chrome://settings/searchEngines`。
- 开发日志（`console.error("[split-search] …")`）。保持现状，不进文案目录。
- e2e 脚本、向导页、报告（`scripts/e2e/**`），这些是开发工具，继续用中文。
- **要翻译**的示例值：对话框占位提示 `例如 baidu` / `例如 百度` / `https://www.baidu.com/s?wd=%s`、引导里的 `gb`、“kg 关键词”。每种语言给一个当地常用、且满足“可作左侧”规则的例子（如英文用 Wikipedia 的搜索网址），作为单独的 key。

## 8. 与语言相关的格式

- 数字：界面里只有常量（id 1–20 个字符、名称最多 40 个字符）。走占位符，用 ASCII 数字。阿拉伯语和印地语的界面里用西文数字是常见做法，不用 `Intl.NumberFormat`。
- 复数：没有随运行时数量变化的句子，不需要 `Intl.PluralRules`。阿拉伯语里“20 个字符”“40 个字符”的名词形式由翻译直接写对。以后如果加入“共 N 个引擎”这类句子，要按 CLDR 复数规则拆 key（阿拉伯语有 6 种形式），到时再定方案。
- 日期、时间、排序：界面上没有日期；引擎顺序由用户决定，不按字母排序。
- 文字长度：西班牙语一般比英文长 20%～30%，印地语、阿拉伯语的字形更高。按钮和标签要能换行，9.3 的冒烟截图覆盖这一点。

## 9. 测试策略

### 9.1 新增 `test/i18n-catalog.test.js`（纯 node）

- `src/_locales/` 下恰好是这 6 个目录，且都在 CWS 支持列表里；`default_locale` 对应的目录存在。
- 6 份 `messages.json` 的 key 集合完全相同；同一个 key 在各语言里声明的占位符名称集合相同；文案里出现的 `$NAME$` 都已声明，声明的都被用到；没有空文案。
- key 只含 `[a-z0-9_]`。
- manifest 里的每个 `__MSG_x__` 都存在。
- 静态扫描 `src/**/*.html` 的 `data-i18n` / `data-i18n-attr` 和 `src/**/*.js` 中 `t("…")` / `tNodes("…")` 的字面量 key，都必须存在；反过来，目录里没被引用的 key 报错（错误码按 `ERROR_CODES` 表计入引用）。
- 每种语言的 `ext_description` ≤ 132 个字符（CWS 摘要上限）。
- 守门：`src/` 下除 `_locales` 外的 `.js` / `.html` 不得出现汉字，注释除外（防止有人又把中文写回代码）。

### 9.2 现有单元测试

- 断言中文的地方大多是附带的，改为断言错误码：`trigger.test.js`（`/未知引擎：nope/` 等 5 处）、`options-edits.test.js`（`/默认组合/`、`/小写字母/`、`/已被占用/`、`/保留参数/` 等 6 处）、`engines.test.js`（`/_ss.*保留参数/`）、`config-store.test.js`（`/配置过大/` 3 处）、`options-ui.test.js`（3 处）、`manifest.test.js`（`default_title`）。
- 测试名（`test("manifest 满足硬约束", …)`）和测试数据里的中文（引擎名“百度”）不是界面文字，不改。
- `options-edits.test.js` 的 `LEFT_RULE` 断言改为断言对应 key 存在。

### 9.3 e2e

e2e 现在有不少按中文文字判定的地方：`optpage.mjs` 的 `btn(row, "授权")` 按按钮文字找按钮（授权、删除、隐藏、编辑、恢复），`options-b.mjs` 找含“没授权”的提示、等“已复制”，`options-b2.mjs` 检查确认框含“网站搜索”，`flow.mjs` 检查 go.html 显示“不会自动重复”“标记参数格式不对”“未知引擎：nope”。另外，测试浏览器的界面语言并不固定（`labels.mjs` 的注释说“可能是英文”），扩展本地化后，界面会跟着变成英文，这些判定会全部失败。

处理：
1. **锁定语言**：`config.mjs` 启动 Chrome 时设置环境变量 `LANGUAGE=zh_CN`（Linux 上界面语言看这个变量，Chrome 文档如此说明）并加 `--lang=zh-CN`；准备阶段读 `chrome.i18n.getUILanguage()`，不是 `zh-CN` 就报“前置条件缺失”。这一步会让测试配置里 Chrome 自己的界面也变成中文，`labels.mjs` 的中英对照仍然有效。
2. **按 key 找元素，不按文字**：`h()` 生成按钮时带上 `data-i18n` 属性（由 `t()` 的调用方传入），`btn(row, "授权")` 改为 `row.querySelector('[data-i18n="engine_grant"]')`。
3. **文字判定改为与 `getMessage` 的结果比较**：在页面里执行 `chrome.i18n.getMessage("go_err_unknown_engine", "nope")` 得到期望文字，再和页面内容比较，不再写中文字面量。
4. **新增 I18N 冒烟步骤（auto，可无头）**：对 6 种语言各起一个临时配置（放在本次运行的临时目录，不碰 `~/.cache/split-search-e2e/profile`），`LANGUAGE=<语言>` 启动，用 CDP `Extensions.loadUnpacked` 临时加载扩展（临时配置重启后丢失也没关系），检查设置页和 go.html 出错页：`<html lang>`、`dir` 正确，没有 `missing message` 控制台错误，没有元素的文字等于 key 本身，没有横向溢出。每种语言各截一张图存进报告目录，供人工检查和商店截图使用。能否在临时配置里用 `loadUnpacked` 是 spike S3。S3 要验证的前提：CDP 的 `Extensions.loadUnpacked` 只在 Chrome 以 `--remote-debugging-pipe` 启动并带 `--enable-unsafe-extension-debugging` 时可用（走 `--remote-debugging-port` 时不可用）；新版正式版 Chrome 已不再支持 `--load-extension`，不能拿它当退路。S3 具体检查：① Chrome 155 正式版用 `--user-data-dir=<临时目录> --remote-debugging-pipe --enable-unsafe-extension-debugging` 启动，`Extensions.loadUnpacked` 返回扩展 id；② 加载后能打开 `chrome-extension://<id>/options.html`，`chrome.i18n.getUILanguage()` 等于 `LANGUAGE` 指定的语言；③ 无头模式（`--headless=new`）下同样成立。现有 `scripts/e2e/config.mjs` 已带 `--remote-debugging-pipe` 和 `--enable-unsafe-extension-debugging`，冒烟步骤沿用这组参数，只换 `--user-data-dir` 和 `LANGUAGE`。

### 9.4 Windows 冒烟

`docs/acceptance-v0.1.md` 第 2 节加一项：Windows Chrome 切换到英文界面（设置 → 语言 → 以此语言显示 Chrome）后，设置页、go.html、工具栏按钮标题都是英文。阿拉伯语的镜像效果以 S2 的截图和母语审校为准。

## 10. 文案润色与翻译流程

顺序固定：**先定中文源文案，再翻译**。源文案改一次，6 种语言都要跟着改，所以源文案要在翻译前定稿。

1. **抽取**（机械操作，不改措辞）：把现有中文原样搬进 `zh_CN/messages.json`，同时完成第 5 节的代码改造。此时界面在中文下和现在完全一样，跑一遍完整 e2e 就能验证。
2. **润色中文源文案**（用户待办，2026-10-24 已记录）：对整个 `zh_CN/messages.json` 用 humanizer（中文用 humanizer-zh）和 lieflat-less-ai-tone 统一处理，用户确认后冻结。商店详情的中文稿 `docs/store/listing.zh-CN.md` 同批处理。
3. **术语表**：仿照 `scripts/e2e/steps/labels.mjs` 的做法，分别以 6 种语言启动 Chrome 155，从 `chrome://settings/searchEngines`、`chrome://extensions` 的 `loadTimeData` 读出 Chrome 自己的界面文字（搜索引擎、网站搜索、添加、设为默认、开发者模式、网站访问权限等），整理成术语表。设置页引导用户去点的 Chrome 菜单名必须和用户看到的 Chrome 界面一字不差。“分屏”在各语言的 Chrome 里怎么叫也从这里取。
4. **英文**：用 content-l10n skill 从中文源文案翻译，附上术语表和每条的 `description`；再用 humanizer 清理 AI 腔；用户审定。英文同时作为后续翻译的参照稿。
5. **繁体中文**：用 content-l10n 从简体本地化，不能只做字形转换（OpenCC 之类）。用词按台湾惯例（网址 → 網址、设置 → 設定、默认 → 預設、授权 → 授權），Chrome 菜单名按术语表。
6. **西班牙语、印地语、阿拉伯语**：用 content-l10n 起草，以中文为源、英文为参照，附术语表。
7. **母语审校（风险）**：印地语和阿拉伯语作者都读不了，机器起草的错误自己发现不了；阿拉伯语还牵涉 RTL 下的标点、混排和“左/右”术语（6.4）。建议这两种语言上线前必须有母语者审校。西班牙语和繁体中文建议审校，但不阻塞上线。找不到审校者时的取舍见第 13 节问题 3。
8. **以后改文案**：改 `zh_CN` 的某条时，在同一提交里更新其他 5 种语言。来不及翻译时先填英文，并在 `description` 末尾标 `[needs-translation]`，catalog 测试只警告不报错，发版前清零。

## 11. 商店详情（与 docs/store 的关系）

## 13. 待用户决定的问题

1. **语言怎么选**：只跟随浏览器界面语言（建议），还是要在设置页里加语言切换（需要自己实现文案加载，manifest 简介和按钮标题仍跟浏览器走）？
2. **第 5 种语言**：阿拉伯语（建议，Ethnologue 2026 第 5 名，但要做 RTL 和母语审校）、法语（只差 100 万人，成本低），还是两者都上？
3. **印地语、阿拉伯语上线前是否必须有母语者审校？** 建议必须。如果短期找不到审校者，可选：(a) 推迟 v0.2，等审校；(b) v0.2 先发 `en`、`zh_CN`、`zh_TW`、`es`，`hi`、`ar` 审校后在 v0.2.x 补上（建议）；(c) 机器起草加交叉回译检查后直接上线，并在详情里注明。
4. **`default_locale` 用 `en`**（建议）还是 `zh_CN`？
5. **产品名**：所有语言都用 `Split Search`（建议），还是某些语言的商店名称加本地副标题（如“Split Search 分屏搜索”）？名称不超过 75 个字符。
6. **繁体中文用词**：按台湾惯例（建议，与 Chrome zh-TW 界面一致），还是另外照顾香港用词？
7. **路线图**：多语言占用 v0.2，原定 v0.2 的模式 B 顺延到 v0.3，是否同意？
