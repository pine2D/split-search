# 搜索分屏联动关闭

2026-11-01 用户在三轮 Claude Code 论证和本机探针后同意实施。

## 行为

- “搜索组合”卡增加默认关闭的开关。启用后，关闭本扩展搜索分屏的一侧时，自动请求关闭另一侧；左右均适用。
- 只认互指、同一有效 `splitViewId`、`mode: split`、两侧 `role: search` 的记录，不认网址兜底。右键查询对、窄窗口相邻对、手动分屏不参与。
- 启用时核实现有搜索分屏并纳入；之后新建/补成的搜索分屏同样纳入。查询对经搜索动作变成搜索对后按新角色处理。
- 页面后来跳转到其他内容仍联动。关闭最后一侧可以关闭该窗口，不加“最后窗口例外”。整窗关闭只清理，不发出额外关闭。
- 明确观察到拆开、移出窗口或改配后解除。拆开后马上关闭的一次性快照可能与直接关闭相同，尤其 SW 冷启动时；此 API 边界已告知并经用户接受，提示常驻开关旁。不承诺安全等待时长或误关概率。
- 本地关闭开关保存成功后，不再发起联动；已经发给 Chrome 的请求无法撤回。取消页面的离开确认后，原配对已解除，不重试关闭。

## 状态、并发和故障

- `storage.sync.closePairTogether` 仅严格 `true` 表示启用，缺省 false。
- **调整 session 约定**：增加 `linked:<splitViewId>`，值为两个已核实的标签 id（升序）。不复制查询词或网址；local 不变。只有后台写许可，删除于解除、消费、关闭或关闭开关；没有记录或实际布局不符不签发。
- 后台顶层同步注册相关事件。`onUpdated` 只处理 `splitViewId`；开关关时移除监听，开启时重新注册。动态注册必须经休眠/冷启动实测，失败则采用始终注册、关闭时立即返回的方案。
- `onUpdated(-1)` 同步段立即发出单次 `tabs.query({})`，只取 id（不是规范承诺的“原子快照”）。同实例内两侧 -1 都观察到同一侧已不在、另一侧还在，才留下短暂候选。两侧还在即解除；未知或事件不齐不关闭。
- 候选、设置修订号、移出/改配的撤销信号只在 SW 内存，不持久化或延时重放。SW 中途终止允许漏关。
- 用一把同源、独占 Web Lock 协调本扩展的标签动作：go 的重新读取/判定/执行、弹窗读取与切换、后台快捷键/查询/补成/联动生命周期。内部状态函数不重复拿锁。锁等待可中止；缺少锁能力时关闭功能失效，其余原有功能可继续。
- 导航、`leaveTab`、设置进度写入、等待消息回复和用户对话框在锁外。自动 `tabs.remove` 只发出，不 await、不 return 其 Promise，不占住队列；异步拒绝经 safe-error 记录，不重试。
- 自动关闭在锁内重新核对记录、许可、偏好、对侧位置。先成功删除旧记录/许可，再读取对侧，最后同步复核撤销信号并发出关闭。消费失败不关闭。新的配对记录不能被旧清理删除。
- 浏览器和其他扩展不受本扩展的锁约束，`tabs.get` 到 `tabs.remove` 的外部变化仍是 API 边界。存储/API 错误不授予新的关闭资格。

## 实现边界

- 不改 manifest 权限、公钥、minimum Chrome155、版本号；无新依赖、内容脚本、网址监听或 keepalive。
- 生产 JS 每文件不超过300行；纯判定在 lib，Chrome 调用在 chrome。
- 四语言一起补齐文案，复用现有 switch 行；说明覆盖范围、导航后仍联动和快速拆开风险。
- 单测/序列测试：默认关、仅明确搜索对、消费失败、取消关闭后 pending、设置切换、对侧改配、事件缺失、整窗关闭、储存故障、跨上下文并发。
- 浏览器验收：真实 Ctrl+W/关闭按钮/中键，两侧，暖/冷 SW；正常拆开、重拼、跨窗口移动、右键查询/相邻对排除；开关与多语言布局；现有分屏/设置回归。

## 已有证据与范围

- 本机 Chrome156.0.8078.79：冷 SW 下直接关闭与 unsplit 后立即关闭有相同事件/查询结果，单次样本不能推出概率。
- 同版 `tabs.remove` 在 beforeunload 取消后1秒和4秒仍 pending，随后真正销毁标签才 resolve。无权限扩展页和 SW 可共享 Web Locks；持锁页/worker 销毁后锁释放。
- 对应 Chromium revision `a21ce95c24ce3964416f09ae1862f53f319eb4d0` 的 tabs_api.cc、tab_strip_model.cc 与上述关闭行为一致；“关闭其他/右侧标签”保护被点击分屏的两侧。
- Windows 与最低支持版 Chrome155 尚未实测，不将 Linux156 的通过写成全平台通过。新增验证结果记在验收文档。
