## 1. 授权提示收敛（P2，quieter）

**现状**：引擎列表里每个没授权的引擎都显示警示图标和警示色的“未授权”，首屏一片黄。实际上只有默认组合的左侧必须授权，其余引擎只在用户拿它作左侧时才需要授权。

**改成**：
- 默认组合左侧没授权：保持现状（警示图标、警示色、“未授权（必需）”、突出的授权按钮）。
- 其余没授权的引擎：中性样式，图标换成不带感叹号的空心圆（`ui/icons.js` 新增或复用），灰字“未授权（可选）”一类文案（新键，四种语言），授权按钮普通样式。刚保存还没授权的引擎（`attention`）仍突出授权按钮。
- 已授权的不变。
- 状态仍靠图标加文字区分，不只靠颜色。

## 2. 设置页去重（P2，distill）

**现状**：“开始使用”卡显示时，默认组合的触发网址同时出现在卡里和“添加到 Chrome”卡里；“其他组合”生成器用和默认组合卡一样的左右窗格，看起来像在改默认组合。

**改成**：
- “开始使用”卡显示时（`setupShown`），“添加到 Chrome”卡里的默认组合一段收进一个 `<details>`（summary 用新键，类似“默认组合的触发网址”），默认收起；卡片不显示时照常展开显示，不包 `<details>`。
- “其他组合”整段收进 `<details>`（summary 用现有 `guide_other_pairs_title`），默认收起；展开状态跨重渲染保留（同现有 `gen` 的做法，记在模块变量里）。
- 生成器的两个下拉框改成普通的“左侧 / 右侧”两个带标签的下拉框（沿用右键查询卡的 `.lookup-pickers` 排版），不再用窗格。窗格只留给默认组合卡（它就是默认组合）。
- 生成器初值不再等于默认组合：左侧取默认左侧，右侧取第一个既不是默认右侧、也不是左侧的引擎；没有这样的引擎时退回默认右侧。用户改过的选择照旧跨重渲染保留。
- `<details>` 用现有 `disclosure()`（`ui.js`），样式与“注意事项”一致。

## 3. 右键查询卡的以图搜图列表（P2，clarify）

**现状**：以图搜图引擎列表没有小标题，下面两个按钮的文字和“搜索引擎”卡的按钮一样（“从引擎库添加”“新增引擎”），读屏和扫读都分不清对象。

**改成**：
- 列表前加 `<h3>`“以图搜图引擎”（新键或复用 `options_image_engine_label` 的说法，按文案流程定），列表 `aria-labelledby` 指向它。
- 两个按钮的可见文字写明对象，例如“从以图搜图引擎库添加”“新增以图搜图引擎”；四种语言各自按本语言习惯缩短，es 下按钮不换行（I18N 步骤的溢出检查守着）。

## 4. “完成设置”复用已开的设置页

**现状**：弹窗的“完成设置”和“查看第 2 步”每次都 `tabs.create` 新开设置页。

**改成**：
- 弹窗先用 `chrome.runtime.getContexts({ contextTypes: ["TAB"], documentUrls: [...] })` 找本扩展已开的设置页（`options/options.html`，带不带 hash 都算；不需要 `tabs` 权限）。优先当前窗口里的，其次第一个。
- 找到：`tabs.update(tabId, { active: true })`、`windows.update(windowId, { focused: true })`，再发 `runtime.sendMessage({ type: "reveal-setup" })` 让设置页自己滚到卡片、焦点给标题（同一 hash 再导航一次不会触发 `hashchange`，所以不靠改网址）。设置页只接受发送方是本扩展 `popup/popup.html` 的这条消息；SW 的 `runtime.onMessage` 遇到这个 type 不回复、不记错误（`lib/messages.js` 的校验按需扩展，先写测试）。
- 没找到，或上面任何一步抛错：退回现在的 `tabs.create(options.html#setup)`。
- 动手前先在 Chrome 156 上实测 `getContexts` 从弹窗里能列出设置页标签、带 `tabId`/`windowId`（结果写进实施报告）；实测不行就退回现状并在报告里说明。

**实测与实现细化（2026-10-26，Chrome 156.0.8078.47）**：
- 真弹窗里 `getContexts({ contextTypes: ["TAB"] })` 能列出已开的设置页，带 `tabId`/`windowId`。`documentUrls` 要求网址连 fragment 一字不差（`options.html` 匹配不到 `options.html#setup`、`#guide` 等），所以不用它：只按 `contextTypes` 取，再由 `lib/messages.js` 的 `pickOptionsTab` 按路径认 `options/options.html`（任何 hash、查询串都算）。
- `runtime.sendMessage` 是广播，会送到所有开着的设置页；所以消息带上目标标签：`{ type: "reveal-setup", tabId }`，设置页用 `tabs.getCurrent()` 读自己的 id 比对，只有被选中的那一页滚动、拿焦点（校验在 `acceptRevealSetup`：发送方是本扩展 `popup/popup.html`，带不带查询串都算，且 `tabId` 相符）。
- 同一窗口里换活动标签时 Chrome 立即关掉弹窗，逐个 `await` 的话后面的调用发不出去；所以 `tabs.update`、`windows.update`、`sendMessage` 同步发出，之后才等结果。弹窗不等设置页回复；`sendMessage` 的拒绝只记 info（经 `safe-error`）。
- e2e：B19 (d) 测复用（已开设置页时点“完成设置”不新开标签，原设置页成为活动标签、焦点在卡片标题）；(a') 先关掉所有设置页再点，测退回 `tabs.create` 的路径（`scripts/e2e/steps/b19-popup.mjs`）。

## 5. 删除确认不再限时

**现状**：`confirmStep` 第一次点击后 3 秒内再点才删，读屏用户来不及（WCAG 2.2.1）。

**改成**：去掉超时。进入“确认删除？”后一直保持，直到再点一次（删除）、按钮失焦或按 Esc（复原）。重渲染时按钮本来就是新建的，自然复原。`armNotice` 播报不变。`test/options-ui.test.js` 跟着改（不再测超时复原，改测失焦和 Esc 复原、长时间后再点仍删除）。
