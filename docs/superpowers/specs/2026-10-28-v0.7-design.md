## 2. A：小改动

### A1 开关滑块

现状（`src/options/options.css` 的 `.switch`）：轨道 34×20，滑块是 `::after`，`top: 3px; left: 3px; width: 14px; height: 14px`，开启时 `left: 17px`。在 WSL 的 Chrome 里按 1、1.25、1.375、1.5 倍缩放渲染都居中，复现不出用户截图的样子。截图实测：轨道约 50×28 像素，滑块约 22 像素宽、上边距约 5、下边距约 2、右边距约 3，说明 Windows 上滑块的尺寸和位置都没有按轨道对齐。

改法：滑块的尺寸和位置都从轨道推出来，不写死像素。

- `::after`：`top: 3px; bottom: 3px; left: 3px; aspect-ratio: 1; width: auto; height: auto`。高度等于轨道高度减 6，宽度跟着高度走。
- 开启时：`left: auto; right: 3px`。
- 轨道尺寸、颜色、焦点框、`forced-colors` 分支不变。
- 验证：本机按 1、1.25、1.375、1.5 倍缩放渲染两种状态（开、关），量出滑块上下、左右的边距相差不超过 1 个设备像素。这一步在本机原本也能过，证明不了 Windows 上已修好，所以必须请用户在 Windows 上再看一眼（第 6 节手测项）；还不对就再来一轮。截图里轨道是主题绿色，说明用户没开高对比度，`forced-colors` 分支不是原因，不改。

### A4 点悬浮层外部关闭

覆盖 5 个对话框：

| 对话框 | 类型 | 点外部 |
|---|---|---|
| `#catalog-dialog` 右侧引擎库 | 列表 | 直接关闭，效果同“关闭”按钮 |
| `#image-catalog-dialog` 以图搜图引擎库 | 列表 | 同上 |
| `#engine-dialog` 新增或编辑引擎 | 表单 | 没改动就关闭（同“取消”）；改过就弹出保存确认 |
| `#image-dialog` 新增以图搜图引擎 | 表单 | 同上 |
| `#rule-dialog` 新增或编辑规则 | 表单 | 同上 |

- **什么算“点外部”**：主键的 pointerdown 和 click 都落在对话框矩形以外的遮罩上。在输入框里按下、拖到外面松开（选文字）不算。只认主键，不处理右键、中键。实现上自己监听，不用 `closedby="any"`：它会把 Esc 和点外部合成同一个 cancel 事件，分不开“Esc 照旧”和“点外部要问”。
- **Esc 和“取消”照旧**：直接关闭，不问，也不改现在的焦点归还逻辑。
- **“改过”的判断**：对话框打开、各字段填好初值之后，记一份表单快照（每个 input、textarea、select 的 value，单选框、复选框的 checked）。点外部时和当前值比，有任何不同就算改过；改了又改回原值算没改过。危险区（`confirmStep` 的“确认删除？”状态）不算改动。
- **保存确认**：新增一个模态对话框 `#discard-dialog`，叠在表单对话框上面：
  - 标题：“保存修改吗？”。不加正文。
  - 按钮从右往左依次是：“保存”（主按钮），对表单 `requestSubmit()`，走原来的提交流程。校验不过时，确认框关掉，表单对话框保持打开、显示字段错误。“不保存”：两个对话框都关掉，丢弃修改，焦点按“取消”的规则归还。“继续编辑”：只关确认框，焦点回到点外部之前表单里有焦点的那个字段，没有就回第一个字段。
  - 确认框上按 Esc 或点它外部，都等同“继续编辑”。
  - 打开确认框时焦点在“保存”上。
  - 三个按钮都是我的判断：用户说的是“保存/取消确认框”，“取消”可能指“不保存”，也可能指“回去接着改”。所以两个都给，按常见的“保存 / 不保存 / 取消”三按钮来做，第三个写成“继续编辑”，免得和表单里的“取消”混淆。
- **文案**：标题和三个按钮，4 种语言。
- **代码位置**：点外部的判断和快照比较是纯逻辑，放进 `src/options/ui.js` 的一个小工具（`lightDismiss(dialog, { isDirty, onDirty })` 这一类接口，由实现者定）。各对话框在自己的 setup 里接上。任何 JS 文件都不超过 300 行，`ui.js` 放不下就拆出 `src/options/dialogs.js`。

## 3. B：规则可选“去掉命中的词”

### 3.1 用户看到的

规则对话框里，“这些词”下面多一个复选框 `#rule-strip`：“搜索时去掉这些词”。下面一行说明：“例如词是 vd：搜‘vd 猫’时，两侧都只搜‘猫’。搜索里只有这些词时照常搜索。”“某种文字”规则没有这个选项，切到“某种文字”时复选框隐藏，切回来时保留原来的勾选状态。

规则行在目标引擎后面加一个说明，形如“有 vd → YouTube · 去掉这些词”。具体写法由文案流程定，要求不只靠颜色区分。

### 3.2 存储

规则多一个可选字段 `strip: true`，只在 `when: "words"` 且勾选时写入，不勾选时不写这个键。`cleanRules` 只给 words 规则保留 `strip === true`，其他值和 script 规则上的都丢掉。`rulesBytes` 和 8000 字节上限照算。

旧版本（0.5、0.6）不认识 `strip`：它们读的时候丢掉这个字段，在旧版本上编辑任何一条规则，写回时会把所有规则的 `strip` 都丢掉。只在用户同时有新旧两个版本、又在旧版本上改规则时发生，接受，在 CHANGELOG 里写一句。

### 3.3 什么时候去、去掉什么

只有**命中的那一条规则**（`ruleRight` 从上往下第一条生效且命中的）带 `strip: true` 时才去词。不论它是否换了右侧都去：引擎正好是当前右侧，或者目标是“默认组合的右侧”（keep），也照去。这样一条规则的行为不受默认组合怎么配影响。

去掉的是这条规则里**每一个**在查询中出现的词的**所有**出现，判定规则与 `matchWord` 相同：

- 比较在规范化后进行（NFKC、小写、去拉丁变音、空白合一，即 `normalizeText`）。删的是原始查询里对应的那一段原文。原文里没被删的部分保持原样，包括大小写、变音、全角字符。
- 词的端点是连写字符（字母、数字、组合符，不含中日韩泰等不用空格分词的文字）时，原文里紧挨它的字符不能也是连写字符。所以 “vd” 不会从 “vdeo” 里删掉，也不会从 “avd” 里删掉；“vd,” 里的 “vd” 会删掉，逗号留下。
- 中日韩等文字的词按子串删：“视频”会从“猫视频”里删掉，剩“猫”。
- 词内带空格的短语（如 “how to”）整段删，原文里两词之间可以是任意空白。
- 删完后，连续空白并成一个空格，去掉首尾空白。
- 只在规则匹配看的那部分查询里删，即先截前 4000 码点、规范化后前 1000 码点对应的原文。超出部分原样保留。
- **去完是空的**（查询里只有规则词，比如只搜“vd”）：不去词，用原查询，规则仍按命中处理（照常换右侧）。我的判断：两侧都打开空搜索没有意义，原样搜索更不让人意外。
- 规范化和原文对不上的少见情况（例如组合字符写法），这一处不删、保留原文，不算出错。

纯逻辑放在 `src/lib/right-rules.js`（例如 `stripWords(query, words) → string`），文件超过 300 行就拆出 `src/lib/rule-strip.js`。`lib/` 不引用 chrome。

### 3.4 go.html：两侧都用去词后的查询

`ruleRight` 的返回值要能表达“右侧换不换”和“查询改不改”两件事。例如 `{ engine | null, ruleId, query }`：`engine` 为 null 表示右侧不换；`query` 是去词后的查询，没去词时等于原查询。⑦ 的 `ruleSuggestion` 只读 `engine`，行为不变。具体形状由实现者定，要求两个调用方的测试都覆盖。

go.js：

- **右侧**：`expandTemplate(右侧引擎.url, 去词后的查询)`。
- **左侧**：原来永远是 `stripMarker(original)`；带 strip 的规则命中且去词结果和原查询不同时，改成“把原始网址里左侧 `%s` 所在参数的值换成 `encodeURIComponent(去词后的查询)`，再 `stripMarker`”。这是字符串操作，原始网址的其他部分逐字保留，比如用户在 Chrome 网站搜索里自己加的参数。纯逻辑放 `src/lib/trigger.js`，例如 `replaceQuery(originalUrl, leftParam, query)`，`leftParam` 来自 `validateTemplate(left.url)`。
  - 原始网址里找不到这个参数，或者出现不止一次：不去词，两侧都用原查询，记 `console.error`，日志里不带查询和词。不落进“只开左侧”。
- **出错时**：规则或去词过程中的任何错误，都退回“没有规则”，即 `_ss` 原来的右侧、原查询、`stripMarker(original)`，与现在规则出错的处理相同。
- **记录**：两侧记录里的 `query` 都是去词后的查询，也就是真正搜的内容。`auto`（`rule`、`base`）照旧只在右侧真的换了时写。
- **“开始使用”判定、窄窗口、分屏判定**：都不变。
- **防重入**：后退、刷新回到 go.html 时照旧不自动分屏。“重新执行”会再走一遍规则和去词。

CLAUDE.md 机制速览里“左侧网址永远是 stripMarker(original)”要改成新的说法。`test/go-wiring.test.js` 加守卫：去词在展开右侧模板之前，并且在规则的 try 里面；出错时两侧都退回原查询；日志不带 query、词。

### 3.5 其他入口

- **弹窗**：记录里的查询已经没有命中的词。`explainRule` 按记录里的查询重算，算不出命中，返回 null，弹窗显示通用说明（`popup_rule_generic`）和“换回 <原右侧>”。我的判断：不在记录里多存原查询或命中的词，隐私约束不变。“换回”用记录里去词后的查询，只换右侧，左侧不动。
- **⑦ 补成分屏**：只影响建议排序，查询取自结果页，不去词。
- **② 右键查词、快捷键轮换、弹窗换右侧**：不受规则影响，不变。
- **在本扩展的一对里重新搜索**：照 go.html 的流程，按新查询重新比、重新去词。

### 3.6 隐私

去词在本机完成。查询只发给左右两个引擎，和现在一样，只是少了几个词。不新增任何存储键，记录形状不变。日志不带查询、词、去词结果。隐私政策不用改。
