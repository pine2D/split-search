# v0.4 界面整修设计（2026-10-26）

来源：`/impeccable critique` 对设置页、工具栏弹窗、go.html 的评审（23/40，存档在 `.impeccable/critique/`，不进 git）。用户决定（2026-10-26）：5 条全做；先做首次设置；主色改成图标的松绿；并入 v0.4.0（改完重打本地标签 v0.4.0，仍不推送、不上传）。

不变的东西：权限、存储里的查询数据规则、DNR、分屏判定、所有硬约束；界面字体仍用系统字体（Operate 界面，贴近 Chrome 原生）；不加运行时依赖、不加构建工具。

## 1. 首次设置（P1）

**现状**：授权横幅 `#banner`、默认组合、右键查询、添加到 Chrome 分散在 1、2、4 张卡片；首屏 4 个授权入口；设置做没做完，页面不知道。

**改成**：

- 顶部 `#banner` 换成“开始使用”卡 `#setup`，只在没完成时显示，三步编号（顺序本身有意义，所以用编号）：
  1. **授权**：左侧引擎（必需）和右侧（建议）的授权按钮。已授权的一步显示勾和“已授权”，按钮消失。
  2. **在 Chrome 里添加网站搜索并设为默认**：直接内嵌默认组合的触发网址（复制按钮）和 `chrome://settings/searchEngines`（复制按钮），一句话说要填哪三格、设为默认；“详细步骤”链接跳到下面“添加到 Chrome”卡。
  3. **试一下**：按钮“试一下”用 `chrome.tabs.create` 打开默认组合的触发网址（关键词固定为一个示例词，文案键给出），当场证明授权和规则生效（e2e T6 已证明扩展打开的标签会被重定向）；下面一句“再到地址栏搜点什么，分屏打开就说明设置完成”。
- **完成判定**：设置页监听 `chrome.storage.session.onChanged`，出现新的 `role: search` 记录、且两侧标签都不是“试一下”按钮打开的那个标签时，说明用户从地址栏或拖拽真的触发成功 → 第 3 步打勾，写 `chrome.storage.local` 的 `setupDone: true`（只有这一个布尔值，不含任何查询数据），卡片换成一句“设置完成”的确认，下次打开设置页不再显示。授权被撤销（左侧未授权）时卡片重新出现，只显示第 1 步的问题。
- 只看“试一下”打开的那一对不算完成：它绕过了用户的网站搜索设置。
- **实施中的修订（2026-10-26，整体审查后）**：上面“设置页监听”的做法在设置页没开时判不出完成，升级来的老用户会一直看到这张卡。改为：“试一下”打开的标签 id 存进 `storage.session` 的 `setupTryTabs`（只有标签 id）；go.js 在一次触发写入一对 search 记录后（新开一对、相邻对，以及本扩展一对里再次触发的整对改写），两侧标签都不在 `setupTryTabs` 里就写 `setupDone: true`；设置页只监听 `storage.local` 的 `setupDone` 变化。不再用 BroadcastChannel；⑦ 补成分屏和右键查询不写 `setupDone`。
- 授权入口去重：`#setup` 显示时，默认组合卡里的 `options_left_not_granted` 提示框、组合生成器里的 `guide_left_not_granted` 提示框不显示（引擎行里的授权按钮保留）。
- 卡片顺序：开始使用 → 默认组合 → 添加到 Chrome → 右键查询 → 搜索引擎 → 快捷键。
- 横幅里“拦截搜索请求”的说法改掉，改成用户能理解的“扩展要在左侧引擎的网站上把搜索转成分屏”一类说法（文案在第 6 节流程里定稿）。

## 2. go.html 出错页（P1）

- 结构：扩展图标（`icons/icon-48.png`，装饰性，`alt=""`）+ 标题 `#status`（正文色，约 18px、半粗）+ 出错细节（正文色，放在 1px 边框、淡危险色底的块里，不用粗色条）+ 按钮。
- 按钮层级：“只打开左侧搜索”是主按钮（有左侧网址时）；“打开设置”是次级；“重新执行”在防重入状态下是主按钮。
- `#status` 加 `role="status"`（礼貌播报）；错误块保留 `role="alert"`。
- 错误文案补原因和做法，至少：`err_unknown_engine`（这条网站搜索指向的引擎已被删除或改名 → 在 Chrome 搜索引擎设置里删掉或改正它，或在设置页重新添加）、`_ss` 格式不对、左侧网址无效。逐个检查 go.js 用到的错误码。
- 不再自带色板：样式移到 `src/go.css`，用共享色彩变量（第 3 节）。

## 3. 视觉：松绿主色、共享变量（P2）

- 新建 `src/styles/tokens.css`，三个界面都引用它（设置页、弹窗用 `@import` 或 `<link>`，go.html 用 `<link>`）；`popup.css` 顶部“两处要一起改”的注释与 `test/popup-css.test.js` 改成检查三者都引用同一份变量文件。
- 主色取自图标的松针绿 `#507665`（暖雾灰 `#8C8881` 作右侧窗格的辅助色）。具体取值由实现时计算，硬要求：`--accent` 上的 `--accent-text` ≥ 4.5:1；`--accent` 作文字（链接、焦点环以外的强调文字）在 `--surface` 上 ≥ 4.5:1；深色模式各自提亮后同样达标；焦点环 ≥ 3:1。`--ok`（已授权、成功）和松绿同属绿色系，必须靠图标区分，不能只靠颜色。
- “已授权”标签对比度 4.43:1 → 调到 ≥ 4.5:1（`--ok` 或 `--ok-soft`）。
- 左右窗格：默认组合卡的两个下拉框、组合生成器、弹窗的左右事实行做成镜像图标的两个窗格（左：松绿淡底 + 松绿细边；右：暖灰淡底 + 暖灰细边），中间不再用孤立的竖线字符；窄宽度上下堆叠时也成立。
- 触发网址框不再卡中卡：去掉 `.trigger-card` 的边框和圆角，改成分隔线或只留淡底。
- 去掉超过 1px 的彩色侧边条：`.engine-row.in-pair` 的 3px 内阴影删掉（行里已有“默认左侧/右侧”标签）；toast `.notice` 的 4px 左边条改成状态图标 + 1px 着色边框。
- 用 Unicode 字符代替图标的地方（授权状态 ●/○、上移下移 ↑/↓ 等）换成内联 SVG，统一线宽，`aria-hidden="true"`，可访问名称不变。
- 浏览器自带的表面也要上色：`::selection`、`accent-color`（复选框）、`caret-color`、焦点环，都取自新变量。

## 4. 说明收起来（P2）

- “注意事项”6 条收进 `<details>`，`<summary>` 用现有 `guide_caveats_title`。
- 右键查询卡的隐私说明和两条图片限制收进 `<details>`（summary 新键）。
- `lang_note` 从页头右上角移到页面底部的页脚。
- 预置引擎行不显示网址（编辑对话框里照常显示）；自定义引擎保留网址。
- 引擎行标签精简：去掉“自定义”（有网址的就是自定义）和 id 标签（id 只在编辑对话框里显示）；“可作左侧”改成只在不能作左侧时显示“只能作右侧”；保留“默认左侧/默认右侧”“建议只作右侧”。目标：es 下一行不换行。

## 5. 表单、可访问性、弹窗细节（P2）

- 新增引擎对话框：字段顺序改成 名称 → 网址 → id；id 标签走 `_locales`（修正“界面文字只在 _locales”的硬约束违规）；id 按名称自动生成（复用 edits.js 的去重逻辑，非 ASCII 名称回退到网址 host 再回退 `engine`），放进对话框里的 `<details>`“高级”，可改；编辑已有引擎时 id 只读显示。
- 变灰按钮（组合在用的引擎不能隐藏/删除）：原因写成行内小字，不只放 `title`。
- 两个“复制”按钮的可访问名称带上对象（“复制默认组合的触发网址”“复制组合生成器的触发网址”）。
- `#setup` 用 `role="region"` 加标题；授权状态变化走 `#notices` 播报。
- 删除：不用 `confirm()`。按钮点一次变成“确认删除？”（3 秒内再点才删，失焦或超时复原），删除后 toast 不变；隐藏不确认（随时能恢复），toast 带“撤销”按钮。以图搜图引擎删除同样处理。
- 弹窗与快捷键：搜索对的“把右侧换成”列表和快捷键轮换都排除当前左侧引擎（`lib/popup-view.js`、`lib/cycle.js`，先写测试）；查询对不受影响（左侧是网页）。
- 弹窗分屏外的状态：在现有一句话下补“在地址栏搜索，或把文字拖到标签栏试试”和当前默认组合（左｜右两个窗格的缩小版）。
- 弹窗底部显示快捷键状态：已绑定显示组合键；未绑定显示“设置快捷键”，点了打开 `chrome://extensions/shortcuts`（与设置页快捷键区相同做法）。
- 统一说法：“打开设置”与“打开设置页”统一成一种（四种语言各自统一）。
- 引擎库对话框：打开时的焦点框只在键盘打开时出现（`:focus-visible` 语义）；每行显示网址的 host 作为预览。
