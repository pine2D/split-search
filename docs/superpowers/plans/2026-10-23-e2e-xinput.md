# e2e 真实输入自动化（xinput）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把引导式验收里的拖拽、地址栏、右键和 chrome://settings 网站搜索操作改成脚本用 xdotool 真实输入 + CDP 自动完成并自动判定，xinput 不可用时回退为现有 assist 步骤。

**Architecture:** 新增 `xinput.mjs`（xdotool 薄封装）、`screen.mjs`（坐标/选区/标签测量/新焦点窗口）、`gesture.mjs`（带防干扰的手势）、`settings-se.mjs`（网站搜索快照与增删改）、`steps/xauto.mjs`（xauto 步骤）；runner 按 xinput 可用性在 xauto 与 assist 版本之间选择。

**Tech Stack:** Node 24（`node:child_process` execFile、`node:test`）、CDP（现有 cdp.mjs/browser.mjs）、xdotool、ImageMagick `import`、xdpyinfo。

**Spec:** `docs/superpowers/specs/2026-10-23-e2e-xinput-design.md`（技术依据：`.superpowers/sdd/2026-10-23-e2e-and-default-pair/spike-xdotool.md`，执行者必须先读 spike 第 1、3 节）。

## Global Constraints

- 无 npm 依赖；外部命令只用 `xdotool`、`import`、`xdpyinfo`，一律 `execFile`（不经 shell），参数不得拼字符串命令行。
- 窗口查找必须 `xdotool search --all --pid <chrome pid> --onlyvisible --class google-chrome` 并核对 WM_CLASS 含 `~/.cache/split-search-e2e/profile`；每次 mousedown/mouseup 与每次按键前断言目标窗口，不符即中止该手势。
- 坐标公式：`X = round((screenX + (outerWidth−innerWidth) + clientX)·dpr)`，Y 同理；禁止使用 `getwindowgeometry` 的 Position。
- 键盘手势只在 `Target.createTarget({url, newWindow:true})` 新开并经 `getactivewindow` 断言获得焦点的窗口里做。
- xauto 只用 ASCII 关键词；`typeAscii` 遇非 ASCII 抛错。
- 网站搜索专用快捷字词前缀 `sse2e`，网址只指向模拟引擎；不得修改/删除用户的其他条目；快照存 `.e2e/settings-snapshot.json`（网址脱敏），结束（含中断）恢复默认引擎并删除专用条目，遗留快照启动时先恢复。
- 启动后窗口固定 normal 1600×1000（`Browser.setWindowBounds`）。
- 防干扰：手势前静止采样指针 2 次（300ms），变化则等 3s 重采，连续 3 次变化 → 步骤 skip（“检测到用户在操作鼠标”）；手势中 move 后读回位置不符即中止；失败最多完整重建现场重试 2 次并记录第几次成功。
- xinput 可用 = DISPLAY 存在、三个命令可执行、`xdpyinfo -queryExtensions` 含 XTEST、非 headless、未传 `--no-xinput`；不可用时 xauto 步骤回退 assist 版本，不算失败。
- 不改 `src/` 与 manifest；不加扩展权限；每个 JS ≤ 300 行；中文文案；报告/日志经 redact。
- 提交身份 `git -c user.name=pine2D -c user.email=oumu323@gmail.com commit`，Conventional Commits，trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。

## Review Focus

1. **合成输入落到用户的 chrome-dbg 等其他窗口**：期望中止手势、该步骤 fail/skip 并写明原因，绝不在别的窗口松开鼠标或按键。用例：Task 2（窗口断言单测）、Task 4（gesture 的防误投路径单测）。
2. **用户在运行中动了鼠标**：期望检测到后等待/跳过，不硬做。用例：Task 4（指针采样逻辑单测）。
3. **标签很多变窄、有标签组或主题不同导致测不出唯一区段**：期望“环境不支持”而非猜坐标。用例：Task 2（RGB 扫描单测含多区段/无区段）。
4. **中断时专用网站搜索条目和默认引擎未恢复**：期望下次启动先恢复。用例：Task 3。
5. **新窗口没抢到前台**：期望不按键、重试或回退。用例：Task 2/4。

### Task 2: xinput.mjs 与 screen.mjs

**Files:** Create `scripts/e2e/xinput.mjs`、`scripts/e2e/screen.mjs`；Test `test/e2e-xinput.test.js`、`test/e2e-screen.test.js`。

**Interfaces (Produces):**
- `xinput.available() → Promise<{ ok: boolean, reason?: string }>`
- `xinput.findWindow(pid, profileDir) → Promise<string /*wid*/>`（核对 WM_CLASS）
- `xinput.pointer() → Promise<{ x, y, window }>`、`move(x,y)`、`down(btn)`、`up(btn)`、`click(btn)`、`key(combo)`、`typeAscii(s)`（非 ASCII 抛 `Error("xauto 只支持 ASCII：…")`）、`activeWindow() → Promise<string|null>`；内部 `run(args)` 用 execFile 并带超时。
- `screen.cssToScreen(m, x, y) → {x, y}`，`m = { screenX, screenY, outerWidth, innerWidth, outerHeight, innerHeight, dpr }`
- `screen.scanTabSegments(rgb, width, rows, bg) → Array<[L, R]>`（纯函数：在给定行段里找比 bg 亮的连续区段，去掉宽度 <90 的）
- `screen.metrics(browser, targetId) → m`；`screen.selectionCenter(browser, targetId, text) → {x, y}`（在页面里插入并选中文字，返回屏幕坐标）；`screen.tabRect(browser, ext, wid, tabId) → [L, R] | null`（激活标签、`import` 截 RGB、scan，唯一区段才返回）；`screen.newFocusedWindow(browser, url) → { targetId, wid }`（断言 activeWindow===wid，否则抛 `Error("新窗口未获得前台")`）。
- [ ] 先写纯函数单测：cssToScreen 用 spike 实测值（screenX 8、screenY 36、outer/inner 1754/1754、1048/961、dpr 1.5、clientX/Y → 期望 X/Y）；scanTabSegments 用合成 RGB（单区段、多区段、窄按钮区段被去掉、无区段 → []）；typeAscii 对 "中" 抛错；findWindow 解析 `xdotool search` 输出并在 WM_CLASS 不符时抛错（execFile 可注入）。RED → 实现 → GREEN。
- [ ] 真机核对（测试配置，带界面）：启动 → metrics → selectionCenter → tabRect 对 2–3 个标签返回 [L,R]，与 spike 数量级一致；findWindow 命中测试窗口而非 chrome-dbg（pointer().window 对照）。贴输出。无残留 Chrome。
- [ ] 提交 `feat(e2e): xdotool wrapper and screen geometry`。

### Task 4: gesture.mjs 与 xauto 步骤

**Files:** Create `scripts/e2e/gesture.mjs`、`scripts/e2e/steps/xauto.mjs`（可拆分）；Modify `scripts/e2e/steps/index.mjs`、`scripts/e2e/args.mjs`（`--no-xinput`）、`scripts/e2e/run.mjs`（启动时 available()、固定窗口尺寸、向导卡片“自动操作中”）；Test `test/e2e-gesture.test.js`、`test/e2e-xauto.test.js`。

**Interfaces:** `gesture.idle(xi) → Promise<"ok"|"busy">`（采样逻辑可注入时钟/指针）；`gesture.dragText(ctx, { fromTargetId, text, to: {x,y} })`；`gesture.contextMenuPick(ctx, { at, itemIndex, expectItems })`；`gesture.omnibox(ctx, { text, altEnter? })`（内部 newFocusedWindow）。每个手势：idle 检查 → 窗口断言 → 执行 → 读回校验；失败抛带原因的 Error。xauto 步骤 `{ id, kind: "xauto", fallback: <assist step>, run }`；runner/selectSteps：xinput 可用 → 用 xauto 版本，否则用 fallback；`--auto-only` 时 xauto 也执行（它们不需要人）。
- [ ] 单测：idle 的三种结果（静止→ok、一次变化后静止→ok、连续 3 次变化→busy）；窗口断言不符时中止且不调用 up/key；重试逻辑最多 2 次并记录 attempt；selectSteps 在 available=false 时选 fallback、true 时选 xauto；xauto 步骤 ASCII 关键词校验。
- [ ] 实现 T1、T2(a)、T2(b)、T3(a)、T4、T5-DRAG、T6-NTP、T11、T14 的 xauto 版本：用 settings-se 建 `sse2e` 系列快捷字词（模拟引擎；T14 用各真实引擎作左侧时也只建 `sse2e-<id>` 条目并在结束删除），判定复用 util 的 waitState/findPair（非 ASCII 判定不适用，因为只用 ASCII）。T14 保留 SW 核实（sw.mjs）。
- [ ] 真机：`npm run e2e -- --auto-only --headed` 全部通过（含 xauto）；连跑 3 次记录各 xauto 步骤的 attempt 分布；`--no-xinput` 时这些步骤回退为 assist（用 `--only T3 --no-xinput --timeout 5000` 冒烟）。无残留 Chrome，settings/storage 均恢复（读回对比）。
