# Split Search v0.2 多语言 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把扩展所有界面文案搬进 `src/_locales/<l>/messages.json`（en、zh_CN、zh_TW、es），由自带加载器按设置页所选语言（默认跟随浏览器）取用，术语与 Chrome 155 各语言界面一致，以发布 v0.2.0 结束（不上架）。

**Architecture:** `src/lib/i18n.js`（纯逻辑：语言解析、占位符替换、标记切分）+ `src/lib/errors.js`（错误码）+ `src/chrome/i18n.js`（`fetch` 包内 `_locales`、`t()`、`applyI18n()`）。lib 和 `edits.js` 只返回错误码，页面层翻译。静态 HTML 用 `data-i18n`，动态节点用 `ht()`（同样带 `data-i18n`，供 e2e 按 key 找元素）。选择存在 `storage.sync.uiLocale`，设置页 `render()` 发现变化就重载文案、重写静态文字、重建动态部分。

**Tech Stack:** Chrome MV3（Chrome 155），原生 ES 模块，无构建、无依赖；Node 24 `node --test`；e2e 为 `scripts/e2e`（CDP）。

**Spec:** `docs/superpowers/specs/2026-10-24-i18n-design.md`（已批准）。另有用户 2026-10-24 追加的三条决定，见下方 Global Constraints 最后三行。执行者两份都要读。

## Global Constraints

- 语言恰好 4 种：`en`、`zh_CN`、`zh_TW`、`es`；`"default_locale": "en"`；`zh_CN` 是源文案。
- manifest `name` 保持字面量 `"Split Search"`；所有语言都叫 `Split Search`，不加本地副标题。
- 无构建工具、无运行时依赖；`src/lib/` 不得引用 `chrome`；JS 单文件不超过 300 行；永远不用 `innerHTML`。
- 唯一允许的 `fetch` 在 `src/chrome/i18n.js`，形式为 `fetch(chrome.runtime.getURL(...))`，只读包内 `_locales/*/messages.json`。
- `storage.sync` 顶层键 `uiLocale`，值为 `"auto"`、`"en"`、`"zh_CN"`、`"zh_TW"`、`"es"`；键不存在或值不认识都按 `"auto"`。
- key 只用 `[a-z0-9_]`；前缀 `ext_`、`go_`、`options_`、`engine_`、`guide_`、`notice_`、`err_`、`common_`、`lang_`；一句完整的话一个 key，不拼句子；每条必须有 `description`。
- 占位符一律具名（`$ENGINE$`），`content` 为 `$1`…`$9`，`example` 必填；字面 `$` 写 `$$`；引号、冒号、句末标点写在各语言文案里（简体“”和全角冒号，繁体「」，英文 " "，西语 « » 或 " "）。
- 不翻译：产品名、预置和自定义引擎名、网址/网址模板/`%s`/`_ss`/引擎 id/`chrome://settings/searchEngines`、`console.error("[split-search] …")` 开发日志、`scripts/e2e/**` 的向导页和报告。
- 要翻译的示例值（对话框占位、引导里的 `gb`、“kg 关键词”）各自单独一个 key，每种语言给当地常用、满足“可作左侧”规则的例子。
- 每种语言的 `ext_description` ≤ 132 个字符。不做 RTL。CWS 提交属于 v0.3，不在本计划。
- CLAUDE.md 其余硬约束（权限、DNR、`key`、`_ss`、预置引擎等）一律不变。
- 提交：Conventional Commits，`git -c user.name=pine2D -c user.email=oumu323@gmail.com commit`，最后一行 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。
- **决定 1（术语）**：各语言的功能术语与 Chrome 155 对应语言界面一字不差，以 `docs/i18n/chrome-terms.md`（任务 1）为准。zh_CN 用 Chrome 的“拆分视图”取代项目原来的“分屏”。范围：扩展界面、go 页、README、`docs/store/` 文案、`assets/templates/i18n/zh_CN.json`（重渲图片）、CLAUDE.md 中引用界面文字的地方。
- **决定 2（润色顺序）**：先改术语，再用 lieflat-less-ai-tone 和 humanizer-zh 润色 zh_CN 源文案，冻结后才翻译；英文译稿再过一遍 humanizer。
- **决定 3（e2e）**：`scripts/e2e` 正在 `feat/e2e-automate` 分支上改造（把人工步骤自动化）。任务 11、13 必须等它合入 `feat/v0.2` 之后再做，不得依赖当前 assist/judge 代码的细节。

## Review Focus

1. **存储里的 `uiLocale` 是垃圾值**（`"fr"`、`42`、`null`、旧设备写的 `"zh-CN"`）：页面按跟随浏览器显示，下拉框选中“跟随浏览器”，不报错。测试：任务 2 `normalizeLocalePref`，任务 8 `mergeConfig`。
2. **某个语言的 messages.json 读不到或解析失败**：页面退回英文，再退回 `chrome.i18n.getMessage`；go.html 的分屏路径照常，出错页照样有字，`i18n-pending` 照样去掉。测试：任务 3 `chrome-i18n.test.js`。
3. **运行时值里含 `$`**（引擎名 `A$1B`、`$$cash`、网址里的 `$`）：原样显示，不被再次替换。测试：任务 2 `formatMessage` 的“替换值不再扫描”用例。
4. **lib 产生的错误码在目录里没有 `err_<code>`**：用户会看到裸 key。测试：任务 5 在 catalog 测试里扫描 `fail("…")` / `spec("…")` / `codedError("…")` 的字面量，必须都在 `ERROR_CODES` 里且有 `err_` 条目。
5. **短时间内连切两次语言，或开着两个设置页**：最终两个页面都停在最后一次存储的语言，静态文字和动态部分一致。测试：任务 13 冒烟步骤的“连切”和“第二个设置页跟随”两项。

### Task 2: 纯逻辑 `src/lib/i18n.js`（规模 S）

**Files:**
- Create: `src/lib/i18n.js`
- Test: `test/i18n.test.js`

**Interfaces:**
- Produces:
  - `LOCALES: readonly ["en", "zh_CN", "zh_TW", "es"]`，`DEFAULT_LOCALE = "en"`
  - `normalizeLocalePref(v: unknown): "auto" | Locale`
  - `resolveLocale(pref: "auto" | Locale, uiLanguage: string | undefined): Locale`
  - `formatMessage(entry: { message: string, placeholders?: Record<string, { content: string }> }, subs: string[]): string`
  - `splitMarked(text: string): (string | number)[]`；标记格式固定为 `"" + 下标 + ""`，导出常量 `MARK_OPEN = ""`、`MARK_CLOSE = ""`

- [ ] **Step 1: 写失败的测试** `test/i18n.test.js`
  - `resolveLocale 映射`：`"auto"` 下 `zh-CN`→`zh_CN`、`zh-TW`→`zh_TW`、`zh-HK`→`zh_TW`、`zh-MO`→`zh_TW`、`zh-Hant-TW`→`zh_TW`、`zh-SG`→`zh_CN`、`zh`→`zh_CN`、`en-GB`→`en`、`es-419`→`es`、`fr`→`en`、`""`→`en`、`undefined`→`en`；`resolveLocale("es", "zh-CN") === "es"`（指定优先）。
  - `normalizeLocalePref`：4 种语言和 `"auto"` 原样；`"fr"`、`"zh-CN"`、`42`、`null`、`undefined`、`{}` → `"auto"`。
  - `formatMessage 具名占位符`：大小写不敏感（message `"$Engine$"`、placeholders 键 `engine`）；调换语序（`"$B$ $A$"`，`a:$1`、`b:$2`，subs `["x","y"]` → `"y x"`）；同一占位符用两次；直接写的 `$1`；缺参数给空串；`"$$5"` → `"$5"`；未声明的 `$NOPE$` 原样保留。
  - `formatMessage 替换值不再扫描`（Review Focus 3）：message `"“$NAME$”"`、`name:$1`，subs `["A$1B$$C"]` → `"“A$1B$$C”"`。
  - `splitMarked`：`"a0b1"` → `["a", 0, "b", 1]`；没有标记 → `["abc"]`；空段丢弃。
- [ ] **Step 2: 运行确认失败** — `node --test test/i18n.test.js`，预期 FAIL。
- [ ] **Step 3: 实现**
  `resolveLocale`：`-` 换成 `_` 后按顺序判断 `/^zh_(TW|HK|MO)(_|$)/i` 或 `/^zh_Hant/i` → `zh_TW`；`/^zh(_|$)/i` → `zh_CN`；`/^en(_|$)/i` → `en`；`/^es(_|$)/i` → `es`；否则 `en`。
  `formatMessage` 必须单遍替换，插入的值不再参与扫描：

```js
const TOKEN = /\$\$|\$([A-Za-z_@][A-Za-z0-9_@]*)\$|\$([1-9])/g;
// $$ → "$"；$NAME$ → 声明了就展开 content（content 内只做 /\$\$|\$([1-9])/ 的同样单遍替换），没声明原样；$n → subs[n-1] ?? ""
```
- [ ] **Step 4: 运行确认通过** — `node --test test/i18n.test.js`，预期 PASS。

### Task 3: 加载器 `src/chrome/i18n.js`（规模 S）

**Files:**
- Create: `src/chrome/i18n.js`
- Test: `test/chrome-i18n.test.js`（在 node 里给 `globalThis.chrome`、`globalThis.fetch`、`globalThis.document` 装最小桩）

**Interfaces:**
- Consumes: 任务 2 的 `resolveLocale`、`normalizeLocalePref`、`formatMessage`、`splitMarked`、`MARK_OPEN`、`MARK_CLOSE`。
- Produces:
  - `setLocale(pref: string): Promise<Locale>`：解析语言，并行读所选语言和 `en`（所选为 `en` 时只读一份）。**每份单独 `.catch` 记错并当作 `null`，不会整体 reject。** 设置 `document.documentElement.lang = locale.replace("_", "-")`，记录 `pref` 和 `locale`。
  - `initI18n(): Promise<Locale>`：`chrome.storage.sync.get("uiLocale")`（失败当 `{}`）→ `setLocale(normalizeLocalePref(uiLocale))`。

  - `tNodes(key: string, nodes: Node[]): (string | Node)[]`：用 `MARK_OPEN + i + MARK_CLOSE` 作 subs 格式化，经 `splitMarked` 把下标换回节点。
  - `applyI18n(root: ParentNode = document): void`：`[data-i18n]` → `textContent = t(key, ...JSON.parse(data-i18n-args ?? "[]"))`；`[data-i18n-attr="attr:key;attr:key"]` → `setAttribute`；`<title data-i18n>` 同样处理（即设置 `document.title`）；最后 `document.documentElement.classList.remove("i18n-pending")`。

  - fetch 桩断言请求网址等于 `chrome.runtime.getURL("_locales/<l>/messages.json")` 的返回值。
