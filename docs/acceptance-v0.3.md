# Split Search v0.3 验收清单

扩展 ID 应为 `alngkkgnobglnfbhcplhpaflcgfiajnj`。v0.3 的新功能：分屏状态加固（记录绑定 `splitViewId`）、右侧引擎库、窄窗口降级、工具栏弹窗与快捷键（设计见 `docs/superpowers/specs/2026-10-25-v0.3-split-tools-design.md`）。

v0.1 的 B/T 表（`docs/acceptance-v0.1.md` 第 3 节）照旧有效，运行方式、显示模式、真实输入的前提、报告与结果分类都以它的第 1 节为准。本表只列 v0.3 新增和改写的项目。

## 1. 怎么跑

- 日常回归：`npm run e2e -- --auto-only`。默认在不可见的 Xvfb 里跑，无人值守，xauto 步骤（含 T19 的真实按键）照跑。
- 只跑 v0.3 的项目：`npm run e2e -- --auto-only --only B2,B14,B16,B17,T16,T17,T18,T19,I18N`。
- 存储基线把 `narrowFallback` 写成 `false`：e2e 的窗口宽度不总受控，现有分屏步骤不能被窄窗口降级打乱。只有 T17 删掉这个键测默认值、再测开关。运行前的 storage 快照照常兜底恢复。
- 快捷键：B17、T19 经 `chrome://extensions/shortcuts` 给 `cycle-right` 绑测试用组合键 `Alt+Shift+Period`，步骤结束时改回运行前的绑定（通常是未绑定）。改动前的绑定记在 `.e2e/shortcut-snapshot.json`；运行被中断时收尾会按它改回，强制退出留下的快照在下次启动时先改回。测试配置结束时和开始时一样。
- 快捷键页的结构认不出（Chrome 改版）时按测试设施问题处理：`--auto-only` 记“跳过”并写明原因，引导式运行回退到人工版本。

## 2. B/T 表（注明覆盖方式）

“覆盖”一列的写法同 v0.1：**e2e auto** = 脚本全自动（`--auto-only` 也跑）；**e2e 自动（真实输入）** = xauto 步骤，脚本用真实键盘操作并判定，没有真实输入时换成后面写的回退版本；**e2e judge** = 向导里由你判断（脚本再核对）；**未覆盖** = 本版不测或需要时手测。分屏都用模拟引擎 A ｜ B（`ea`/`eb`，另有路径型模板的模拟引擎 C `ec`）代替真实引擎，链路相同。

### 验收用例 T16–T19

| 编号 | 操作步骤 | 期望 | 覆盖 |
|---|---|---|---|
| T16 | 分屏记录：(a) 触发后读 `storage.session`；(b) `unsplit` 后用 `createSplit` 把同两个标签拼回去，在同一标签连续触发两次；(c) `tabs.move` 对调两侧再触发；(d) 关掉一侧；再构造“对侧已和别的标签重新配对”（直接写 `storage.session`）后关掉旧标签；(e) 重启浏览器后，另一侧停在引擎的非搜索路径时触发 | (a) 两条记录互指、形状正确、`splitViewId` 一致；(b) 两次都判“不是本扩展的”，各新开一对，原来两个标签不被改写；第一次之后失效记录仍保留（互指、旧 `splitViewId`）；(c) 仍就地更新，记录按新位置写；(d) 关之前两条记录都在，关掉后两条都删掉；对侧已重新配对时只删旧标签自己的记录；(e) 判“不是”，新开一对 | e2e auto（含重启；(b) 构造不出新的 `splitViewId`、(e) 重启后没恢复分屏时记“跳过”并写明原因） |
| T17 | 窄窗口降级：CDP 把窗口设到 960 以下；(a) 删掉 `narrowFallback`（默认开启）后触发，同一标签再触发一次；(b) 窄窗口下在用户自己的分屏里触发；(c) 开关设为 `false` 再触发；(d) 宽窗口下触发；(e) 窄窗口建好相邻对后把窗口调宽，同一标签再触发；(f) 窄窗口建好相邻对后把开关设为 `false`，同一标签再触发 | (a) 不分屏，右侧是相邻的后台标签，写 `adjacent` 记录；再触发复用那个右侧标签，不新开；(b) 用户分屏两侧都不变；(c)(d) 照常分屏；(e)(f) 原来的相邻对拼成分屏，记录改为 `split`，不新开标签。结束后恢复窗口尺寸 | e2e auto（窗口设不到阈值以下时记“跳过”） |
| T18 | 工具栏弹窗：(a) 本扩展分屏建好后打开 `popup.html?tabId=<左侧>`；(b) 在弹窗里点模拟引擎 C 换右侧，关键词带特殊字符 `a&b #c+d 中文`；(c) 对用户自己的分屏打开弹窗 | (a) 显示的关键词、左右引擎名与记录一致，可换的引擎不含当前右侧；(b) 右侧网址与 `expandTemplate(C 的模板, 关键词)` 逐字相同，右侧记录的 `engine` 改为 `ec`、关键词不变，左侧记录仍是 `ea`、关键词不变，分屏不拆开，弹窗随之刷新；(c) 只显示“当前标签页不在 Split Search 打开的拆分视图中”的说明 | e2e auto |
| T19 | 快捷键换右侧：经 `chrome://extensions/shortcuts` 给 `cycle-right` 绑 `Alt+Shift+Period`，`cycleExclude` 排除全部预置引擎和模拟引擎 C；在本扩展分屏所在的前台窗口里按两次 | 第 1 次右侧从模拟引擎 B 换成模拟引擎 A（C 和预置引擎被跳过，回到开头；可以与左侧相同），第 2 次换回 B；右侧网址都是 `expandTemplate` 的结果，记录随之更新，左侧网址与记录不动，分屏不拆开。结束后快捷键改回运行前的绑定 | e2e 自动（真实输入：新开窗口拿到前台后用 XTEST 按键）；无真实输入时 e2e judge（脚本照样自动绑定，向导请你在分屏窗口里按快捷键并确认右侧变了，脚本再读记录核对；快捷键页结构认不出时请你自己绑、用完清除） |

### 本版不在 e2e 里测的

- 快捷键在 Service Worker 被回收后冷启动时的表现：e2e 的调试会话让 SW 一直存活（同 v0.1 第 3 节的说明），靠手测。
- 弹窗的真实点开方式（点工具栏图标后在弹窗里操作）：B2 只断言弹窗页出现并渲染，换右侧在 T18 里用 `popup.html?tabId=` 直接打开的页面测。
- 引擎库里各真实网站的预填效果：收录前已人工验证，结果见 spec 附录 A；e2e 不访问这些网站。

## 3. 反馈方式

把整份 e2e 报告（`.e2e/report-*.md`）贴回给 Claude。多子项步骤（B16、B17、T16、T17、T18、I18N）的各子项写在报告的“详细说明”小节里，跳过的子项（如 B16(c)）列在“未覆盖”小节。
